让候选人的 AI 助手直接读到贵公司自己系统里的岗位

给雇主的一页说明。免费、只读、十分钟。排序谁也买不到。

一、这是什么

OpenHire 是一个开源的求职工具（MCP server）。候选人把它装进 Claude、Cursor 这类 AI 助手， 助手就直接从雇主自己的招聘系统（Greenhouse、Lever、Ashby、北森、Moka）的公开接口里读岗位， 不经过招聘平台。候选人的简历只在他自己的电脑和贵公司的投递页之间，永远不经过我们。

索引里的每条岗位都带贵公司系统里记的原始发布日、在架天数和直达贵公司投递页的链接。 数字可以自己核：numbers.json（含口径和实测日期）。

二、贵公司得到什么，永远得不到什么

得到永远得不到（谁也买不到）
  • 贵公司的岗位出现在候选人的 AI 助手里，带贵公司自己系统的发布日，直达贵公司投递页；
  • 认领后：署贵公司名的说明，显示在贵公司指定的岗位旁边；「常年开放 / 难招但在招 / 已停止招聘」的标注；日期语义更正（贵公司系统记的是需求创建日而不是上线日时）；可选的回复时限承诺。
  • 排序位置。排序是（匹配度，新鲜度）的纯函数，被仓库里的测试锁死；
  • 更低的在架评分。它是（重挂次数，在架天数）的纯函数，贵公司的说明显示在它旁边，不改它；
  • 任何付费档位。到今天没有一行计费代码。

三、贵公司的岗位已经在索引里吗

用 Greenhouse、Lever、Ashby、北森、Moka 的雇主，多半已经在了；去 仓库的雇主一节认领即可。

用飞书招聘、只在 BOSS 直聘发布、或者官网自建页面的雇主，现在不在索引里。 不是我们挑的，是读不到：飞书的岗位接口要请求签名，我们视为访问控制、不绕；平台不是贵公司自己的系统，我们不读； 自建页面多数没有机器可读的岗位数据。下面三条路，任选一条，都是只读、免费，十分钟。

四、三条路

  1. 飞书招聘：授权两个只读 scope。在飞书开放平台给我们的应用授权 hire:site:readonly 和 hire:site_job_post:readonly。它们只暴露贵公司已经公开的招聘站和岗位， 不涉及任何候选人数据，撤销只要一下。
  2. 官网自建页面：放一份机器可读的岗位数据。在招聘页里加一段 schema.org JobPosting 的 JSON-LD （Google 招聘用的同一个标准），或者挂一个静态 JSON 文件，把网址告诉我们。模板： 
    <script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "JobPosting",
  "title": "感知算法工程师",
  "datePosted": "2026-10-08",
  "hiringOrganization": {"@type": "Organization", "name": "贵公司名称", "sameAs": "https://贵公司官网"},
  "jobLocation": {"@type": "Place", "address": {"@type": "PostalAddress", "addressLocality": "北京", "addressCountry": "CN"}},
  "description": "岗位描述……",
  "url": "https://贵公司官网/careers/这个岗位的页面"
}
</script>
    每个岗位一段，datePosted 写真实上线日。我们按这个日期算在架天数，并在数据里标明它是贵公司自报的。
  3. 换到一个可公开读取的招聘系统。上面五家任一，把招聘页网址告诉我们即可，其余不用做。

五、怎么联系，多久回复

  • GitHub 表单：雇主认领（中文）， 里面有一项「贵公司的岗位目前发布在哪里」，选了我们就按那条路回；
  • 没有 GitHub 账号：发邮件到 gdchenhao@qq.com，主题写「雇主认领 + 公司名」，用贵公司企业域名邮箱发出来本身就完成了身份核验；
  • 3 个工作日内给结论。身份材料只用于核验，不公开、不留存、不转作他用。

六、边界，先说在前面

  • 我们量得到一个岗位挂了多久，量不到贵公司想不想招。认领就是让贵公司用自己的话解释前者；
  • 我们不在任何文案里点名「某家公司查不到」来催雇主开门。走不走这三条路，是贵公司的决定；
  • 贵公司随时可以要求把贵公司从索引里移除，我们照做，不争辩。
