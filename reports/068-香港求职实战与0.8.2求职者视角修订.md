## 一、求职者侧

### 1. 独特优势怎么定位

ChatGPT 的简历只写到 2023 年的履历，把 2024 年起写成「家庭原因 / 独立顾问」，完全没有 2026 年这一段。而从仓库 67 份 reports、PROGRESS 和私库稿件里挖出来的事实，恰恰是最能抵消「年龄、空窗、英语听力」三个顾虑的东西：

| 别人有的 | 领导独有的（有公开证据） |
|---|---|
| 猎头经验 | 智驾 / 具身 / RISC-V 的深科技人才地图，LinkedIn 7,151 关注者多数是工程师，脉脉 2,858 算法工程师人脉（私库 linkedin-about.md、reports/039） |
| 会用 AI 工具 | 不写代码，用 Claude Code 在 12 周内把一个开源产品从 v0.1.0 推到 v0.8.2：PyPI、官方 MCP Registry、Claude Desktop 扩展、600 多条自动化测试、零密钥的自动发版（reports/008、011、067） |
| 说自己靠谱 | 公开可核的判断力：三条 CI 强制的隐私红线、抓取伦理边界、「动词要有字段撑着」的诚实规矩、公开撤回过一次结论、67 份验收日志连错误一起公开（reports/031、035、037、053） |

定位一句话：**深科技人才与生态的操盘手，同时是 AI 原生的产品负责人**。这类人不是靠「英语母语级」或「年轻」被雇的，是靠「知道谁在做什么」加「能把想法变成交付」被雇的。能发挥这个组合的岗位类型：
- AI 公司（具身 / 智驾）的**人才负责人 / 高级招聘专家**：他们缺的正是懂这个赛道人才地图的人，年龄在这类岗位是资历不是减分；
- **开发者生态 / 合作生态 / 标准化合作**类岗位：OpenHire 的上架、社区、雇主侧 GTM 就是现成作品集；
- **创新生态 / 大学合作 / 项目经理**（他已投的 HKSTP 方向）：原简历已覆盖，新简历把 2026 年的交付加进去，空窗期变成「期间做了什么」。

对三个顾虑的处理方式：年龄不写、不解释；空窗期写成「2024 年因家庭原因转为兼职顾问，2026 年 7 月起全职做 OpenHire」，用交付物说话；英语只写「专业工作水平，读写强、与海外团队日常书面沟通」，不写母语，不夸口。

## 二、项目经理侧

### 1. 这次真实使用暴露的问题（五个维度）

| 维度 | 这次体验 | 打分（求职者视角，满分 10） |
|---|---|---|
| 便捷 | 一行安装；助手一句话就能搜、查、拿链接；但查企业要先把 JD 复制给工具 | 7 |
| 金钱成本 | 全程零费用，唯一付费项用求职者自己的 key | 10 |
| 时间成本 | 搜索加查证十分钟内完成；但香港岗位只有 10 条，大量时间要去索引外 | 7 |
| 高效 | 没有「岗位关闭 / 重新出现」的生命周期信号，没有投递难度，没有 HR 族 | 6 |
| 可信 | 一手数据、不给判决、不碰简历；但受限网络下三项查证把「没连上」写成「查不到」，会误导 | 8 |

合计约 **76 / 100**，没到 100。差距主要在覆盖面（香港只有 3 家）和生命周期信号，不在代码质量。

### 2. 0.8.2 当天修的（602 tests，推 main 后由 `release.yml` 自动发 PyPI、tag、mcpb、Release）

1. **`check_employer(job_id=...)`**（CLI `--job`）：雇主和红线词筛查直接取索引里那条岗位的标题加 JD，助手查刚搜到的岗位不用再复制文本。实测六条岗位。
2. **`unavailable` 项带 `reason`**：`network`（这次查询没连上来源，说明的是网络不是雇主）与 `no_record` / `http_status`（来源答了没记录）分开，说明文字也分开；工具说明告诉助手怎么说。
3. **香港与境外的免费核验路径**进 `pending_user`（公司註冊處、防騙視伏器、OpenCorporates）。
4. **红线词表**补繁体写法（包機票、無需經驗、日結……）和香港警方的求职骗局特征（押金、培训费、无需面试、Telegram、WhatsApp only）。

隐私说明不用改：只加了链接，没有新的网络请求。

### 3. 他山之石（调研摘要，出处在 `reports/068` 同日的调研记录，均为 2026-10-10 实查）

- **hiring.cafe / Hirebase / findyourrolefirst**：每条岗位带 first_seen / last_seen 和 NEW / UPDATED / REAPPEARED / EXPIRED 生命周期，`get_changes` 能说「上次看后已关闭」。
- **Otta / Indeed**：把雇主响应率做成**量到的字段**（两周内有无明确结果、滚动 90 天；Indeed 的 Responsive employer 要 30 天响应率超 51%），不是幽灵判决。
- **LinkedIn**：「Reposted」会重置日期，显示的岗位年龄只是下限；认证徽章附一句「不代表更可能被录用」。
- **Greenhouse 2024 报告**：平台数据每季 18 到 22% 岗位无招聘活动；学界估计约 21%；行业共识是「30 天只是代理指标不是验证」，与我们「只说量到的」一致。
- **香港**：Scameter 无公开 API，只能深链；公司註冊處有 data.gov.hk 开放 API（按名称或 BRN 查成立日期，条款与限流未验证）；GLEIF 免费、OpenSanctions 批量数据 CC BY-NC。
- **MCP 生态**：job 类 MCP 普遍停在几十到几百 star，ATS 直读的同类全在 0 到 2 star；上千 star 的要么有厂商背书，要么像 linkedin-mcp-server 那样把所有安装路径都铺齐并持续维护。ChatGPT 里已有 @Indeed 应用（2026-02），「在用户已经聊天的地方出现」是通路。
- **AI 原生岗位**：Forward Deployed、AI Enablement / Adoption Lead、Builder in Residence 等头衔要的是「交付过的作品加前后对比」，不是工具清单；香港 Cyberport 招聘会约 60% 岗位与 AI 相关，雇主强调「AI 应用不只属于技术人员」。

### 4. 定位与路线图修订（建议，领导定）

定位不动主句（「让 AI 助手直接从雇主自己的系统里替你找工作，简历不出你的电脑」），把第二句从「原始发布日」升级为「**找得到、看得清、查得了**」：找得到是索引，看得清是在架时长与生命周期，查得了是企业查证台。查证台应当**对索引外的公司也有用**，这是这次最明显的体会：香港 10 条岗位之外的世界，工具只能给域名三项加链接。

按价值排序的下一步（已做的不列）：
1. 岗位生命周期：`first_seen / last_seen / lifecycle`（new / updated / reappeared / closed）+ `check_watches` 报「已关闭」。中等工作量，周快照已有全量对比的基础。
2. `relist_count > 0` 时把年龄写成下限（「重新发布过；首次见于 N 天前」）。小。
3. 投递难度 / 投递通道字段（雇主 ATS 单页表单 vs Workday 式多页）。小到中。
4. 企业查证加免费的制裁与 LEI 核对（OpenSanctions 批量、GLEIF）和香港公司註冊處开放 API（先验证条款与限流，再上）。中。
5. 认领雇主的 SLA 改成量到的响应率并照抄 LinkedIn 那句「不代表更可能被录用」。中。
6. 香港覆盖：按第三份调研的种子表加香港 AI / 具身雇主（只加在 Greenhouse / Lever / Ashby / Moka / 北森上的）。小。
7. `role_family` 加 HR 族与 AI-enablement 族，并提示这类岗位要作品集。要全量重抽，约 ¥6，低价时段。
8. 分发：补齐 Codex 插件等安装路径；ChatGPT Apps 需公网端点，仍不可。
