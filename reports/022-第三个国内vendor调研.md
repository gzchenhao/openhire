# 022 · 第三个国内 ATS vendor 可行性调研

**日期：** 2026-09-07　**执行人：** Claude（PM 会话）　**花费：** ¥0（只读探测）

## 调研问题
在已打通的北森(beisen)、Moka 之外，是否存在**第三个值得开发的国内 ATS vendor**——判据两条同时满足：①赛道公司（自动驾驶/具身智能）有实际采用；②技术上可公开抓取，不碰"签名/验证码/登录墙"红线。

## 方法
①正向：探主流国内招聘 SaaS 的公开接口可达性；②反向（更关键）：对尚未覆盖的赛道头部公司做 ATS 指纹鉴定，看它们**实际在用**什么系统。地面真相由②决定——vendor 值不值得开，取决于赛道公司是否在用。

## 国内 ATS 格局与评估

| 平台 | 赛道采用 | 可抓性 | 结论 |
|---|---|---|---|
| 飞书招聘 (jobs.feishu.cn) | **最高**（小马智行、Momenta、地平线…） | ❌ 请求签名 `_signature` + 滑块验证码 = 访问控制 | **红线不碰**（014 已判，CLAUDE.md 判例） |
| 北森 (zhiye.com) | 中（宇树/优必选/普渡…12家） | ✅ 已打通 | 已用 |
| Moka (mokahr.com) | 中（小鹏/速腾/元戎…14家） | ✅ 已打通 | 已用 |
| SmartRecruiters | **零**（赛道无一家） | ✅ 有公开 API | 无意义 |
| Workday / SuccessFactors | 极少且非赛道 | ⚠️ per-tenant 复杂 | 不值得 |
| 大易 Dayee / 仟寻 / e成 | 未见赛道采用 | 多为招聘方后台，无公开职位 API | 无意义 |
| 智联/前程/BOSS/猎聘 | — | 是**聚合平台**非一手 ATS | 定位红线排除（只收一手信源） |

## 反向指纹鉴定（尚未覆盖的头部公司实际在用）
- **小马智行 Pony.ai** → 飞书（`www.pony.ai/careers` 含 `jobs.feishu` 指纹，2026-09-07 复验）
- **Momenta** → 飞书（014 已确认）
- **地平线 Horizon** → 飞书系
- 图森/纵目/毫末等 → 飞书或自建静态页（无标准 API）
- 海外 ATS（GH/Lever/Ashby）上的中国 AV 公司 → 已全部在库（文远知行/Zoox/Nuro/Waymo…）

## 核心结论

**当前不存在值得开发的第三个国内 vendor。** 原因是死结：赛道里"还没覆盖"的头部公司，几乎全部聚集在**飞书招聘**——而飞书是我们红线判定的"不可抓"（签名+验证码=访问控制）。其它有公开 API 的平台（SmartRecruiters/Workday/Dayee）在本赛道**采用率为零或极低**。开一个没有赛道公司在用的 vendor，是纯浪费工程资源。

**即：国内覆盖已达"守红线前提下"的技术天花板。** 北森+Moka 两个 vendor 已收全其上的赛道头部；剩下的名字被飞书这堵墙挡着，且这堵墙我们主动选择不翻。

## 什么会改变结论（触发重启本调研的条件）
1. 飞书公开其招聘数据的正规 API / 合作通道（则合规接入，非破解）；
2. 某批赛道公司从飞书迁移到可抓 ATS（每周快照刷新时 `ohp seed` 会自动发现新可抓租户）；
3. **雇主认领入口**（v0.3 已埋 `employer_claim` issue 模板）带来飞书系公司主动提交——这是绕开抓取墙的正道：公司自己授权，我们不必抓。

## 建议
- **不开第三个 vendor**（ROI 为负）。
- 国内覆盖维持北森+Moka，靠每周 `ohp seed` 自动捡新可抓租户增量。
- 把"扩国内覆盖"的精力**转回 star 增长主线**（punkpeye 合并 → 内容重炮），或转向**雇主侧认领**（把飞书系公司变成主动提交方，而非抓取对象）。
