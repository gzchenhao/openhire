# 034 · 雇主认领：把入口和落地接上（2026-09-14）

## 背景

体验官把 `response_sla_days`「自 0.1 空到 0.5」列为未修缺陷。复查后我的判断是：
**它不是缺陷，是协议里唯一一个「雇主声明」字段**——我们观测不到回复，因为投递直达雇主官网、
从不经过服务端（`delivered_via` 恒为 `employer_site`，`Application` 表 CI 强制无 PII）。
要推断它就得经手投递或经手回信，两者都踩第一条红线。**null 是诚实答案。**

领导追问：「雇主侧数据你能拿到吗？」→ 拿不到。
再追问：「那要马上启动雇主认领这条线吧？万一有雇主认领呢？」→ **这一问问到了真问题。**

## 二、已补的落地能力

### 1. 存储：SLA 存在**公司**上，读取时套用

```
companies + response_sla_days, claimed_at   （forward-only 迁移，与 posted_at/role_family 同一套）
```

**为什么不存在岗位上**：存公司上，一次认领就能扛过每周重抓，并自动覆盖雇主之后新发的岗位，
不需要人工重新应用。岗位级若将来有值仍然优先。

### 2. 持久化：认领是**仓库里的声明式文件**，不是数据库状态

这是我第一版漏掉的关键缺口。CI 每周一从已发布快照重建全库
（`ohp seed` → `ohp ingest --all` → `ohp snapshot-build`），
**只存在维护者本地库里的认领，下周一会无声消失。**

于是认领改为放 `src/openhire/seed/claims.py`，和公司种子同一个做法：

- **声明式且权威**：`apply_claims` 让数据库向文件对齐，**删掉条目即撤销认领**
- `ohp seed` 每次运行都重新套用 → CI 每周自动重放 → 认领随快照发布出去
- 每份认领是一个**可审阅的 diff**，带日期和「如何验证的」备注（不含姓名/邮箱）
- 幂等，有测试

### 3. 顺带核实（而不是假设）的一件事

`seed_companies()` 对已存在的公司**只写** name / ats_vendor / ats_tenant / careers_url，
不会重置 `verified` / `response_sla_days` / `claimed_at`。
我加了测试把这个赋值集合读出来钉死——否则将来有人在 seed 里多写一行，认领就会静默消失。

### 4. 兑现模板里承诺的「verified badge」

`get_company_info` 新增 `claimed` / `claimed_at` / `response_sla_days`。

**注意**：v0.1 有过一个 `verified` 字段，恒为 false，后来被删掉了——
**一个永远为假的信任信号只会误导人**。名字不再复用，改叫 `claimed`，
且只有在真有认领时才为真。

### 5. 维护者命令

```bash
ohp claim fftai --sla-days 7     # 记录一份已验证认领
ohp claim fftai --unverify       # 撤销
```

它会**打印出该加进 `claims.py` 的那一行**，防止「只在本地生效」的认领被当成全部记录。

### 6. 文档：把 null 的含义写清楚

README 与 MCP docstring 措辞一致：

> `response_sla_days` 几乎每行都是 null，**而这个 null 是有意义的**：
> 它是雇主自己承诺的回复窗口，只在认领后才有值。我们从不推断、不估算——
> 原理上就观测不到回复。读作「这家还没人认领」，**不是「数据缺失」，更不是「回得慢」**。

## 三、红线

`test_claiming_cannot_touch_rank` 与 `test_applying_claims_never_touches_ranking_inputs`
断言认领路径的**代码体**不出现 `rank_score` / `match_quality` / `freshness` / `ghost_score`。

第一版这个测试挂了——它 grep 整段源码，**命中的是 docstring 里「排序买不到」那句承诺本身**。
改成剥掉 docstring 只查代码体。要检查的是代码干了什么，不是文案说了什么。

## 四、验收

- **300 tests 全绿**
- 实测：认领傅利叶后其 17 个岗位全部带上 `response_sla_days`；Waymo（未认领）仍为 null；撤销后归零
- 过程中我用字符串切片改 docstring 把 `mcp_server.py` 改出语法错误，
  被 collection error 当场拦下；改用 Edit 精确替换修复

## 五、还差的不是代码

**雇主不会来我们的 GitHub。** 认领入口埋在 README 的 Roadmap 里，而 HR 和招聘负责人不上 GitHub；
139 家公司没有一家被告知过自己在索引里。

所以「启动雇主认领」的真实动作是**去告诉雇主**，这一步需要领导的人脉和名义，我做不了。
最轻的起手式：挑 2–3 家领导有熟人的公司私下问一句。
**一份成功的认领比一百个 star 更有说服力**——它是第一个雇主承认这套数据是对的。
