## 三、任务 A · GLM 后端接入与选型

### 做了什么

`DeepSeekExtractor` 本来就是 OpenAI 兼容的，所以**没有新写一套 HTTP 栈**，而是把它抽成可配置的基类（`_payload` / `_call` / `parse_json_object`），`GLMExtractor` 继承它并只改三处 provider 差异：

- `thinking: {"type": "disabled"}`（见上）
- `max_tokens` / `rf_max_tokens` 均 ≥ 1024
- 不发 `response_format`（coding 端点支持，但关思考后照样可能带围栏，真正的保障是**剥围栏的容错解析器**，多发这个字段只白花 prompt token）

配套改动：

- **`extraction_source` 如实标 `'glm'`**，绝不冒充 deepseek。
- **选取条件从 `!= 'deepseek'` 改为 `NOT IN ('deepseek','glm','anthropic')`**。这是必须改的：两个 LLM 后端并存时，旧条件会让 glm 和 deepseek 互相无限重抽对方的行，白烧配额且毫无质量收益。
- **429 退避**：`_retry_call` 遇 429 按 2/5/12/30 秒退避重试；连续 5 个岗都死于 429 就**停在断点**（进度已逐批提交，重跑自动续上）。
- **成本按后端算**：`cost_cny(pin, pout, backend)`，GLM 费率 0 —— token 照样统计上报，只是不产生现金。
- 新命令 **`ohp extract-compare`**：拿库内已有的 deepseek 结果当基准，只让挑战者发请求，所以选型本身也是 ¥0。

## 五、任务 C · 每周快照自动刷新（GitHub Actions，云端零密钥）

### 做了什么

新增 `.github/workflows/refresh-snapshot.yml`：每周一 06:10 UTC + 手动 `workflow_dispatch`。

流程严格按任务书：**下载已发布快照 → `ohp seed` → `ohp ingest --all`（强制免费启发式）→ `ohp snapshot-build`（零用户态校验原样跑）→ `gh release upload v0.1.0 … --clobber`**，最后两步是自证：把刚发布的资产**按公开 URL 重新下载**验证，再以**全新用户身份跑一次 `ohp bootstrap`**。

**零密钥，逐条落实：**

- `permissions: contents: write`，**仅此一项**（没有 `id-token`、没有 `packages`）。
- **没有建任何 GitHub Secret**；工作流里唯一的凭据是 `GH_TOKEN: ${{ github.token }}`——GitHub 每次运行自动下发、随作业结束失效的 token，**不是仓库密钥，无需轮换**。
- `OPENHIRE_EXTRACTOR: heuristic` 写死在 job env 里。不写也没 key，但显式写死能防住「将来有人往 CI 塞 key 就开始花钱」。
- 抓取读的是公开 ATS 端点，本来就不需要凭据。
- 全文 grep `secrets.` / `api_key` / `Bearer` / `ZHIPU` / `DEEPSEEK` → **零命中**。

**两个刻意的设计决定：**

1. **从已发布快照起步，而不是空库。** 这样 `first_seen_at` / `relist_count` / `ghost_score` 和**已有的 LLM 抽取结果**都会延续，不会每周被重置。已验证：CI 跑完后，公开快照里 `glm` 的 1,749 条**原样还在**（`ingest` 只在 `content_hash` 变化时才重抽）。
2. **抓取失败不许静默。** 新增 `ohp ingest --fail-over N`：失败家数 > N 就以非零退出，让 GitHub 默认失败邮件发出来。CI 用 `--fail-over 10`。默认（不带该参数）行为完全不变，交互式使用不受影响。有 4 项单测锁死阈值语义（10 家过、11 家挂、不带参数永不挂）。

### 代码改动：为什么不能直接改 slug

`companies.id` 就是我们的公司 slug，而**每条职位的主键是 `{company_id}:{ats_job_id}`**。如果按新 tenant 重新入库，就会新建一行公司、老公司行连同它的全部历史职位一起变成孤儿。

所以给 `Candidate` 加了可选的 `company_id`：**ATS tenant 可以漂，我们的 slug 钉死**。`seed_companies` 现在用 `cand.slug` 作公司行主键、用 `cand.tenant` 去抓板面，并会就地更新已有公司的 `ats_vendor` / `ats_tenant` / `careers_url`。普通公司完全不受影响（`slug` 默认等于 `tenant`，seed 表仍是二元组，只有这三家写成三元组）。
