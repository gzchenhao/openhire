## 一、先纠一个事实

star 分析里写：「近 30 条 commit 也**没有一条** `Co-authored-by: Claude` 尾注」。

**这句是错的。** 实测：

```
git log -30 --format='%H%n%b' | grep -ci 'Co-Authored-By: Claude'   →  30
```

不止近 30 条。**从 2026-07-14 的第一个 commit 起，138 个全都带这条尾注。**

但它的**结论仍然成立**，只是理由不同：GitHub 贡献者图里确实只有 `gzchenhao` 一个人
（131 contributions）。原因不是我们没写，而是 `noreply@anthropic.com` 没有绑定 GitHub 账号，
所以 GitHub 不为它建贡献者条目。

**这个区别要记住：我们不是"选择了不挂名"，而是"挂了但没生效"。**
如果哪天那个邮箱被关联到一个 GitHub 账号，Claude 会**自动**出现在贡献者图里，
不需要我们做任何事。那份分析建议的「不要挂进贡献者图」，目前是靠一个我们不控制的外部事实在维持。
暂不处理，但记录在案。

## 二、两份分析独立收敛到同一句话

- star 分析：「瓶颈根本不在要不要披露 AI，而在分发渠道。」
- 知乎分析：「内容做到 90 分，转化做到 20 分。」

**我同意，而且实测数据比两份报告写的更硬。** 今天现拉：

| | 实测 |
|---|---|
| 仓库近 14 天访问 | 123 次 / **76 个独立访客** |
| 其中来自知乎 | **4** |
| star / fork / watch | **7 / 0 / 0** |
| PyPI 近 30 天下载 | 1,210（近 7 天 142，昨天 2） |

**76 个独立访客换来 0 个新 star。** 这是转化断裂最直接的证据，比"知乎 referrer 只有 4"更刺眼：
人已经站到仓库门口了，还是没进去。

PyPI 那 1,210 次下载**不要当成用户数**。我们自己的 CI 每周跑快照刷新、`uvx` 每次调用都算一次下载，
我**分不开机器和人**。按规矩 1，这个数在对外文案里一个字都不能用。
