## 过程中踩的坑（重要，下次直接照做）

知乎专栏编辑器（Draft.js 系）**不接受自动化注入的内容**，这次连踩三层：

1. **`type` 分块打字会乱序。** 每块之间只要有一次 `left_click` 重新聚焦，光标就回到文档开头，于是第 2 块插到第 1 块前面。首次结果是「七 → 五 → 四 → 二 → 三」，第一节整个丢失，结尾句重复两遍。
   - 规律：**同一次聚焦内连续 `type` 是正确追加的**（AAA→BBB 实测通过）；中途点击就废。
2. **`key` 事件完全进不去编辑器。** `ctrl+a`、`Delete`、`Backspace`（×25）、`ctrl+End` 全部无效，编辑器里的字一个都删不掉。能删的只有工具栏的「撤销」按钮（真实点击有效）。
3. **`form_input` 只改 DOM，不进编辑器模型。** 页面上看着 2512 字，页脚「字数」一直显示 15，服务端草稿也只有 `<p>祝各位早日拿到真 offer。</p>`。
   - **代价：第一次点「发布」，文章带着这一行就上线了。** 属于真实事故，几分钟内修复。

### 最终奏效的办法

用知乎自己的草稿接口（和编辑器保存走的是同一个）：

```js
PATCH /api/articles/<id>/draft
headers: { 'Content-Type':'application/json', 'x-xsrftoken': <cookie _xsrf> }
body: { content: "<p>…</p><p>…</p>", title: "…" }
```

写完**必须重新加载编辑页**，让编辑器从服务端读回草稿（页脚字数从 15 变成 2428 即为同步成功），否则页面里的旧模型会在保存时把正文覆盖回去。然后点「更新」发布。

注：「发布中…」按钮会一直卡着不变，**这不代表失败**，两次都是实际已经发布成功，去 `/p/<id>` 验证内容才算数。

## 教训（已可复用）

- 富文本编辑器的自动化，**唯一可信的验收信号是服务端状态**（草稿接口 / 已发布页），不是 DOM，也不是截图。页脚字数计数器这次恰好是准的，它一直在喊 15，我先入为主当成了「懒更新」。
- 发布前的检查顺序应当是：读服务端草稿 → 对长度和首尾 → 再点发布。这次是反过来的，所以出了事故。
- 「幽灵岗位」在知乎不是话题，搜出来的是《试刊号》《犯罪演绎法 2》之类的无关词条。可用的是「求职」「简历」。
