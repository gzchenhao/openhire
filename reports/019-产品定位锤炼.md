# 019 · 产品定位锤炼（三轮迭代定稿）

**日期：** 2026-09-02　**参与：** Howard（领导）· Claude（PM）· 三份外部模拟评审（梁文峰/马斯克/马云视角）· Gemini 复核

## 定位终稿

**一句话（对外）：** OpenHire 是 Agent 原生的求职数据协议层——当替你找工作的从「你刷网站」变成「你的 Agent」，它需要的不是又一个平台，而是一条干净、可信、可编程的一手职位数据管道。

**三层结构（对内，资源按此分层）：**
- **楔子层**（获客）：高活性降噪的一手数据（真实发布日、ghost_score、直达申请）。最小可行覆盖，垂直做全不做广；数据运营 100% 自动化。
- **底座层**（主线）：五协议字段 + MCP 五工具契约 + 结构性隐私。核心研发永远向这层倾斜。
- **终局层**（愿景）：雇主进场后的三方可信管道（认领/状态回传/response_sla/只为结果付费）。不提前建设，只做小范围验证。

## 三条战略铁律（与三条隐私红线并列）

1. **楔子不吞底座**：反幽灵数据是敲门砖不是主业；「必须人肉维护数据」的方案一律否决。
2. **飞轮先验证后扩张**：雇主激励与用户反哺先在自动驾驶/具身智能垂直池跑通，拿到真实行为数据再扩行业。
3. **中立即生命**：只做规则制定者与可信管道，数据生产逐步移交生态；永不偏向任何一方；反哺设计宁慢勿碰隐私红线。

## 本土化修正（对模拟评审的三处不照搬）

1. 单人+AI 团队的真实资源黑洞是**手工宣传动作**而非数据运营（数据管线已全自动）→ 宣传也要工程化。
2. **生态防火墙已存在**：`ohp` CLI 本身就是独立于 Claude/Cursor 的完整客户端。阈值写死：周活跃指纹 ≥500 或生态政策风险信号 → 启动 CLI 体验升级（TUI）。
3. **雇主机制再等一拍**：周活跃指纹过百前不投入研发，只做「零成本隐形预留」（见下）。

## Gemini 复核采纳的两点（已落地）

1. **「反幽灵」话术降火**：对 2B 从「戳穿假岗位」改为「高活性降噪（signal-to-noise）」——长期挂岗常是常青人才池而非假招聘。README 的 ghost_score 定义与 FAQ 已按此重写，为雇主认领留缓冲。
2. **脱敏能力证明（redacted proof-of-fit）进路线图**：候选人授权投递时可附带匿名匹配摘要（仅技能重合度，永不含身份，简历依旧不过服务器）——补上「雇主收到空白申请」的体验缺口。列入 v0.3。
