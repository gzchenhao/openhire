# 150 · 「照片与录像」讲给用户听，以及做全行业要花多少钱（0.8.70、0.8.71）

日期：2026-11-17（云端会话）

## 背景

领导 11-17 两问：① 「网页搜索像拍一张照片，我们的库像录像」这个比方他一听就懂，要让普通用户也听到；② 现在两三个行业两万多条岗位，精抽每月十几元，做全行业全职位（全垒打）是不是负担不起，怎么破。同日另定：装机提示不等实测，先加「聊天窗口装不了」的分支。

## 做了什么

### 1. 装机提示加第三个分支（0.8.70）

助手在这个窗口里根本装不了软件（普通聊天窗口）时，停下来告诉用户在它自己的设置里添加 MCP 服务器（流式 HTTP，地址 https://openhire-vlny.onrender.com/mcp ，不用令牌），不确定菜单就直说、不编菜单名。README 中英、连接向导、求职清单、私库定稿同步。七个助手的聊天窗口实测排在本机待办 44，测的就是新版。

### 2. 「照片与录像」（0.8.71）

查过：知乎稿和 README 此前都没这样讲过。

- 连接向导（中英）和 README 第一屏加一段「为什么不直接让 AI 上网搜」：网页搜索是一张照片，只看得到这一刻，下架的旧岗位也混在里面；OpenHire 是一段录像，每周读雇主自己的系统，记下每个岗位哪天出现、哪周还在、哪天撤下，所以答得出三个问题：挂了多久、投的那个还在不在、这周新出了哪些。
- 对外用「录像」不用「监控」：讲隐私的产品说「监控」容易让人误会成监控人。
- 知乎回答稿一条（私库 `zhihu-photo-vs-recording-2026-11-17.md`），本机待办 45，今晚起找合格的题投。
- 顺手改：首次下载提示里的「约 30 MB」改为「约 60 MB」（公开快照现为 58.9 MB）。

### 3. 全行业的成本：实测数字

取自 11-16 公开快照：

- 在架 27,933 条里，LLM 精抽过的 10,374 条（37%），**只用免费规则的 17,559 条（63%）**。也就是说，索引里近三分之二的岗位今天就没花过 token，搜索、盯岗、日期、下架、职级、学历年限、签证这些功能都照常。
- 每周新进约 3,000 条（近 7 天 3,051 条）。精抽单价：技能约 ¥0.0022 / 条，岗位族约 ¥0.0015 / 条。
- 按比例放大：在架 100 万条（现在的约 36 倍）时，全部精抽一遍约 ¥3,700，之后每月新增约 47 万条，约 ¥1,700 / 月。贵，但不是天文数字。

**结论：token 不是全行业的瓶颈。** 真正的瓶颈是另外三样：

1. **下载体积。** 快照现在 58.9 MB（解压 333 MB）。36 倍就是 2 GB 以上，普通用户下不动。
2. **雇主名单。** 每家雇主的招聘系统要一家家找到并核实，218 家用了四个月。
3. **读不了的平台。** 国内多数雇主在飞书、BOSS 直聘或自建站上发岗，按我们守的红线读不了，这不是钱能解决的。

### 4. 怎么破（建议）

1. **新行业一律不精抽。** 精抽只抽技能标签，只对工程师按技能搜有用。行政、财务、销售这类岗位按岗位名、城市、行业、职级搜，全是免费规则。新行业进来成本为零。
2. **读全文交给用户自己的助手。** 用户的 AI 助手本身就是大模型。今天上线的 `get_job` 把职位描述原文交给它，由它判断合不合适，token 花在用户那边，不花在我们这边。
3. **长尾靠现读，不靠入库。** `read_board` 和 `add_employer` 已经支持「任何行业、任何一家用这 11 种招聘系统的雇主，贴网址就读」，在用户自己电脑上算，我们零成本。全垒打不等于把全世界的岗位都装进我们的库：重点行业入库（有历史、能比较），其余现读。
4. **快照按行业分包。** 用户只下载自己要的行业；不想下载的用托管地址。这是做大之前必须先做的一步。
5. **雇主自报。** 读不了的平台只能靠雇主授权或填表，这条路已有（0.7.0），不花我们的钱。
