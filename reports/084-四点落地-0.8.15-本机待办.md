## 五、云端和本机会话直接沟通

- **今天就能用：「本机待办」。** 私库新文件 `local-inbox.md`：云端把要本机做的日常活写进去，本机每晚定时任务第一步先同步私库、做完待办再做知乎和 GitHub 日检，做完标「已办」。领导不用转贴，只是有一天的延迟。要领导在场的活（输密码、付款、授权第三方应用）不进这个队列。
- **实时直连：远程控制（Remote Control）。** 官方文档（code.claude.com/docs/en/remote-control、cross-session-messaging，10-20 核实）：在桌面版 Code 标签页的本机会话里输入 `/remote-control`（或 `/rc`），确认一次，会话就连上远程控制，并出现在 claude.ai/code 的会话列表里。文档写明连上后「同一条连接也承载来自云端会话的消息」，但没写云端会话怎么找到并寻址本机会话，所以要实测：领导开好后，云端发一条无害的测试消息看能否到达。原生 Windows 上跨会话消息要求 Claude Code v2.1.234 或更新；桌面版里收到的消息可能被挂起等批准（桌面版弹不出批准框，默认五分钟后过期），能否放行由领导决定。
- **定时任务收不到消息。** 文档写明无人值守的定时运行不能接收跨会话消息，所以每晚 21:30 那次只能靠「本机待办」文件取活，这正是今天建的机制。
- 今天的任务书 `local-session-prompt-2026-10-20.md` 里第 2 节就是把「先做本机待办」写进每晚的定时任务，这是最后一次需要领导转贴的日常安排。
