### 3.2 找租户的方法：先摸清「200 到底意味着什么」

任务书提醒过 Moka 对乱写 slug 也返 200。实测把这件事拆成了**三种**不同的 200，而且三种可以精确区分：

| 现象 | 页面标题 | `#init-data` 里有 `org` | 含义 |
|---|---|---|---|
| `app.mokahr.com/apply/<slug>` 302 → `/apply/<slug>/<siteId>`，页面 ~50KB | 公司名 | **有** | 租户存在且在招 ✅ |
| 停在 `/apply/<slug>/<siteId>`，页面 7,558 B | 「当前网页已关停」 | 无 | 租户曾经存在，portal 已关停 |
| 停在 `/apply/<slug>`，页面 4,558 B | 「您访问的页面不存在」 | 无 | slug 不存在 |

**判定标准因此是「init-data 里有没有 `org` 记录」，不是 HTTP 状态码。** 这条规则写进了适配器
（`fetch()` 里的 `if not init.get("org")`），并由两个真实抓下来的 fixture 锁死
（`moka_portal_absent.html` / `moka_portal_retired.html`，两者都是 HTTP 200）。

另外确认：`/apply/<org>`、`/social-recruitment/<org>`、`/campus-recruitment/<org>` 是同一租户的三个入口，
前两个指向同一个社招 siteId，第三个是**另一个** siteId 的校招漏斗 —— 与北森一样，**校招不入库**。

### 3.3 接口：服务端直出 + 一层「自带钥匙」的 AES 信封

一次抓取三种请求（全部免登录、无签名、无验证码）：

1. `GET /apply/<org>/<siteId>` —— 服务端渲染页，隐藏 `<input id="init-data">` 里是**明文 JSON**：org 记录、
   `aesIv`、首屏 15 条职位、`jobStats.total`。
2. `POST /api/outer/ats-apply/website/jobs` `{limit, offset, siteId, orgId, site:"social", needStat:true}` —— 分页全量花名册。
3. `POST /api/outer/ats-apply/website/job` `{orgId, jobId, siteId}` —— **每岗一次**，取 `jobDescription`（列表里没有 JD）。

第 2、3 步的响应体是 `{"data": <base64>, "necromancer": <key>}`，AES-128-CBC。

**为什么这不算「破解」（这是本单最需要向领导交代清楚的一条）：**

- 端点本身**公开、免登录、无签名**，裸请求就能 200；
- **密钥 `necromancer` 就装在它自己加密的那个响应里**；
- IV（`aesIv`）明文躺在任何人都能 GET 到的页面 HTML 里。

也就是说，这里**没有任何秘密可破**、没有身份可冒充、没有频控可绕 —— 它是一层传输编码，等价于「多绕了几道的 base64」。
这和 014 判飞书不可抓的理由是**两回事**：飞书的 `_signature` 是字节跳动的请求签名 + 滑块验证码 SDK，是货真价实的访问控制，
拿不到就是拿不到。本单从头到尾**没有计算任何签名、没有解任何验证码、没有绕任何登录墙、没有规避任何频控**。

（若领导认为这条线仍应画在 Moka 之前，回退成本很低：删 `_MOKA` 名单即可，适配器代码不影响其它 vendor。）

### 3.5 适配器实现（`src/openhire/ats/moka.py` + `_aes.py`）

同北森标准，逐条对照任务书的硬要求：

- **五协议字段齐** —— `verified_at` / `source` / `ghost_score` / `response_sla_days` / `apply_channel` 全部由既有管线填充，
  Moka 侧提供 `ats_job_id`、`title`、JD、`apply_channel`、`location`、`posted_at`。
- **`tenant` = `"<org>/<siteId>"`，`company_id` = 裸 org slug。** 因为 siteId 就是地址的一部分；用 017 给 `Candidate`
  加的 `company_id` 逃生口把两者分开，**将来 siteId 变了也不会让全部历史职位变孤儿**（职位主键是 `{company_id}:{ats_job_id}`）。
- **`posted_at` 用 ATS 真实发布日，取不到落 NULL。** 取值顺序 `publishedAt` → `openedAt` → NULL。
  为什么是 `publishedAt`：在浏览器打开
  `app.mokahr.com/apply/robosense/77883#/job/b9cbf7e6-…`，雇主自己的页面上印的就是**「发布于 2026-08-26」/「发布日期 2026-08-26」**，
  与该岗的 `publishedAt` 逐字对上（其 `openedAt` 是 2026-01-29）。即：**以雇主自己对外公示的那个日期为准**，
  和 ashby 用 `publishedAt`、greenhouse 用 `first_published` 是同一条家规。**任何情况下都不用抓取时刻兜底**（P0-2）。
- **`apply_channel` 直达该公司官方职位页** —— `https://app.mokahr.com/apply/<org>/<siteId>#/job/<jobId>`。
  注意只有 **hash 路由**这一种形式有效：`/apply/<org>/<siteId>/job/<id>` 路径形式实测 **404**（SPA 路由表里就是 `/job/:jobId`）。
  浏览器实测见 §6.2。
- **薪资如实落、`salary_period='monthly'`** —— 见下面单独一段，这是本单唯一一处需要做推断的地方。
- **fixture 单测** —— 44 项，全部用 2026-09-02 真机抓下来的真实响应，见 §6.4。
- **频控保守** —— 模块级 `Semaphore(2)` 把并发 Moka 租户压到 ≤2（严于全局 5）；单租户内**分页串行、详情串行**，
  详情之间再加 `0.2s` 间隔；真实 UA 走全局 `config.USER_AGENT`；同租户 30 分钟下限由既有 `due_companies()` 保证。
- **详情拿不到时不丢岗** —— 重试 1 次仍失败就带空 JD 落库。丢掉它会被下游读成「这岗下架了」，那是**假的下架信号**。

**薪资：唯一一处推断，连同证据一起交代。** Moka 的 `minSalary`/`maxSalary` 是**裸数字**，`salaryUnit` 恒为 0，
同一家雇主同时存在两种量级：速腾聚创的「高级机械结构工程师」是 `35–57`，「机器人运动控制专家」是 `35000–60000`。
两者显然是同一档薪资带的两种写法 —— 小数字就是中文招聘里通用的「K/月」简写。因此规则是：
**两端都 <1000 → ×1000；两端都 ≥1000 → 原样；一大一小 → 判读不出来，落 NULL。** 一律 `salary_period='monthly'`、
`currency='CNY'`，**绝不折年薪**（×12？×13？×16？—— 那是编造）。
**外加一条例外**：`commitment` 为 `实习`/`兼职` 的岗位薪资一律落 NULL —— 它们在同一个字段里填的是**元/天**。
这个例外不是预想出来的，是入库后体检撞出来的，经过与证据见 §6.3。所有分支都有单测。

**为什么自己写了 AES 而不是引依赖（`src/openhire/ats/_aes.py`）：** `openhire` 是 `pipx` 装的 CLI，为了拆一层
「多绕几道的 base64」而把 `cryptography` 这种编译轮子拉进运行时依赖不划算；而且每周快照刷新的 CI 是**零密钥、纯净环境**，
少一个编译依赖少一份出错面。纯 Python 实现只做**解密**，正确性由 **FIPS-197 附录 C 的 128/192/256 三组官方向量**钉死。
S-box 是按定义现算的，不是贴表 —— 可审。

## 五、任务 C · 两个异常北森租户的诊断

### `yijiahe.zhiye.com`（亿嘉和）—— 已修复入库 ✅

同一个标准端点、同一个请求体（`POST /api/Jobad/GetJobAdPageList`，`Category:["1"]` + `DisplayFields`），
现在返回 **`{"Code":200, ..., "Count":134, "Data":[…]}`**，`Content-Type: application/json`。
014 的读数**不再复现** —— 无论当时是站点临时状态还是请求体不全，今天它就是一个正常的北森租户。

（行业口径：亿嘉和主业是电力巡检机器人，与 014 已收录的普渡/海柔/新松同属机器人本体。）

### `zhito.zhiye.com`（挚途科技）—— 查明原因，证据留观 ⚠️

三条实测证据：

1. **它跑的是北森的另一代产品。** 页面资产是 `stc-cms.beisen.com/CmsPortal/6/6_themes_default_*`（旧版 CmsPortal
   template6 + jQuery 3.1.1），不是我们适配的 `tms-recruit` SPA。
2. **旧版根本没有那个 JSON 端点。** `POST /api/Jobad/GetJobAdPageList` 返回的是 ASP.NET 的
   `<title>Not Found</title>` 错误页（HTTP 200 + `text/html`）—— 这就是 014 看到的「非 JSON」，
   不是改版、不是重定向、不是参数不对，**是这个接口在这套部署上不存在**。
3. **就算把接口摸出来也没有东西可抓。** 用 Chrome 打开 `zhito.zhiye.com/social/jobs` 并录网络请求：
   全页 **24 个请求里没有任何职位数据接口**（列表是服务端直出的），而页面上印着 **「无任何在招职位」**。

**结论：不是「做不到」，是「当前没有可抓的东西，且为一个空花名册去适配北森的第二代产品不划算」。**

### 6.3 抓取中发现并修掉的一个会造假的坑：实习岗的「元/天」

首轮入库后做量级体检，发现福瑞泰克有几条离谱数据：**「雷达数据处理算法实习生」月薪 200,000–250,000**。回源查证：

| 职位 | `commitment` | 上游 `minSalary-maxSalary` | 含义 |
|---|---|---|---|
| 雷达数据处理算法实习生 | `实习` | `200-250` | **200–250 元/天** |
| 采购实习生 | `实习` | `150-200` | **150–200 元/天** |
| MCU开发（ADAS产品） | `全职` | `20-40` | 20K–40K 元/月 |
| 高级项目工程师 | `全职` | `25-40` | 25K–40K 元/月 |

同一个字段、同一个 `salaryUnit=0`，**全职填的是「K/月」，实习填的是「元/天」**。我原来的 ×1000 规则会把「200 元/天」变成「月薪 20 万的实习生」——
这正是本项目最忌讳的那种编造。

**修法：`commitment` 为 `实习`/`兼职` 的岗位，薪资一律落 NULL。** 本库没有 daily 周期字段，而把日薪折成月薪（×21.75 个工作日？）
是在替雇主发明一个它从没公示过的数字。宁可缺，不可编。已加 3 条断言（全职照常解析、实习落 NULL、兼职落 NULL）。

**改正存量时踩到的第二层：定向重抓一次并没有把旧数值改掉。** `_update_job` 只在 `content_hash` 变化时才重写薪资，
而 hash 只覆盖标题 + JD —— 解析规则变了、原文没变，于是 620 条全被判为「未变」。
把这 620 行的 `content_hash` 清空后再重抓，才真正走到重抽分支：**620 条全部更新**，
带薪资的行 242 → **232**（10 条日薪岗按规则落 NULL），Moka 最高薪从「实习生 25 万/月」变成速腾聚创
「高级物理AI算法工程师」**55,000–100,000 元/月**，量级合理；`title` 含「实习」且仍带薪资的行 **0 条**。
（这 620 条当时全是 `heuristic` 抽取，重抽不损失任何 LLM 成果。**这一条值得记住：改了解析规则要想影响存量，
必须让 `content_hash` 失效，否则重抓是空转。**）

**另一项体检：14 条空 JD 逐条回源核实。** 结果 **14/14 是雇主自己就没填 JD**（上游 `jobDescription` 长度为 0），
不是抓取失败。这些岗照常保留在库里 —— 丢掉它们会被下游读成一次**假的下架**。
