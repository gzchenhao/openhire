## 背景

## 一、月报页「—」的实现缺口（已修）

说明块写着「本列标『—』意思是不知道」，但渲染表格的那一行没处理 `None`，
实际输出是 `None%`，全页 9 处。**功能只写了文案，没写代码。**

修复：`scripts/build_report_page.py` 的 `rows()` 对 `touched is None` 输出 `—` 并带
悬停说明；`build_report_data.py` 的终端输出同样处理（原本 `{t['touched']:3}` 遇 `None`
会直接 `TypeError`）。

## 二、国内公司在这一列上的结构性不公（已处理）

最后一列是全表**唯一能替雇主说话**的一列（「这家在维护」）。而：

| ATS | 提供 `updated_at` |
|---|---|
| Greenhouse | 91% |
| Moka | 96% |
| Ashby / Lever | 0% |
| **北森** | **3%** |

用北森的公司无论维护得多勤，都只能拿到「—」。**读者顺着这一列看下来，会觉得国内雇主更不上心。**

修复：北森系公司标 `国内*`（Moka 系仍标 `国内`，因为它们拿得到真实百分比，不需要这个辩护），
悬停说明 + 说明块里的可见正文，明确要求不要拿它们的「—」和海外百分比作比较。

## 三、开启 Pages 时把未获批准的月报页发了出去（已撤下）

`gh api -X POST repos/.../pages -f source[path]=/docs` 开启后，站点根即 `docs/`，
**`docs/report/index.html` 随即公开**，带 24 家公司名。而「点名 vs 只发分布」领导从未拍板。

这是越权：把一个对外发布的决定，用一个技术动作绕过去了。

处理（领导选 A：撤下）：
- `docs/report/` → `report-draft/`（移出发布目录，不靠 `_` 前缀的 Jekyll 约定隐藏）
- `docs/report-data.json` → `report-draft/`（它带同样的公司名，留着等于名字照样公开）
- 落地页删除两个链接；两个生成脚本读写路径改到 `report-draft/`

验证（Pages 重建后）：
```
/                  200
/report/           404
/report-data.json  404
/numbers.json      200
```

**教训：凡是会让内容进入公网的操作，先列出「这一步会公开哪些文件」再执行。**

## 五、24 家点名公司刷新：北森 6 家全部失败，且失败是静默的（已修）

刷新结果（13 天窗口）：

| | |
|---|---|
| 新增 | 188 |
| **下线** | **259** |
| 更新 | 51 |
| 未变 | 1,276 |

**259 个岗位在 13 天内下线，占这 24 家的约 14%。** 旧数据里它们全都还挂着——
这独立印证了「点名前必须刷新」，也印证了撤页面是对的。

但北森 6 家（yijiahe / jaka / mechmind / **unitree** / ubtrobot / dobot）全部返回
`新增 0 · 更新 0 · 下线 0 · 未变 0`，且 `verified_at` 没有前进。

根因：
```
IngestStats(companies_crawled=0, companies_failed=1, failed_tenants=['beisen:unitree'], ...)
```
`refresh_company_index()` 不看 `companies_failed`，一律返回 `"refreshed": True`，
CLI 照样打印「✓ 已刷新」。**抓取失败被报告成刷新成功。**

这是最危险的一类 bug：它把一个过时索引洗成看起来新鲜的索引，而**新鲜度就是我们的产品**。
失败形态（全 0）与「这家确实没变化」在字节层面完全相同，所以绿色测试套件也发现不了。

修复：
- `service.refresh_company_index()` 检测 `companies_crawled == 0 and companies_failed`，
  返回 `reason: "ats_unreachable"` + `failed_tenants` + `data_age_days`（告诉调用方手上的数据到底多旧）
- CLI 走 `console.error("ERR_ATS_UNREACHABLE", ...)` 到 stderr 并 `exit 1`，批量循环无法跳过
- 新增测试 `test_a_crawl_that_failed_is_not_reported_as_a_refresh`
- 顺带把节流测试里手搓的 `_Stats` 换成真的 `IngestStats`——
  **只带四个计数器的 stub，正是这个 bug 能在全绿套件里活下来的原因**

## 六、北森失联的性质判定

| 探测 | 结果 |
|---|---|
| DNS | 解析正常（4 个阿里云 IP） |
| TCP 443 | **连通，50ms** |
| TLS 握手（带 SNI） | **成功，1.37s** |
| HTTP 响应 | **永不返回**（30s / 60s 均 ReadTimeout） |
| 对照：Moka / Greenhouse | 302 / 301，正常 |

TCP 通、TLS 通、HTTP 不回话 —— **这是被拦的典型形态，不是接口下线。**

**按 020 号抓取边界判例，到此停手。** 对方把我们挡在门外属于访问控制，
正确动作是停抓并记录，不是换 UA 或改指纹再试——那就是在绕访问控制。

后果：宇树等 6 家的数据停在 2026-09-02，**无法刷新**。领导问的那个场景里，
「发布前先刷新」这条防线**对宇树无效**。

## 结论与下一步

1. 月报页仍在 `report-draft/`，未公开，等领导定夺点名与否
2. 北森系 6 家无法刷新，若要点名，**必须在页面上注明这 6 家的核验日期与其他家不同**，
   或直接把它们排除出点名表
3. 北森失联需要持续观察：若是临时限速，几天后可能恢复；若是永久封禁，
   需要评估国内覆盖的可持续性（北森在架 879 个岗位）
4. 待办：X 线程（领导手发）、雇主认领人选（领导定）、知乎券 2 张 9/30 过期
