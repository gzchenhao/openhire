### 做了什么

|---|---|---|
| ① | `pipx install openhire` | 真跑。pipx 装进隔离的 `PIPX_HOME`（不污染系统），**从 PyPI 真实拉取 openhire 0.1.1** |

**零伪造。** 演示里出现的 job_id 全部可在新快照中查到（它们本来就是从新快照查出来的）：`mongodb:7727896`、`mongodb:7727899`、`samsara:7558088`。

### 一处技术说明（为什么不是直接重定向 stdout）

Windows 上 rich 走 legacy console API（`SetConsoleTextAttribute`）而非 ANSI 转义，所以 `ohp … > out.txt` 拿到的是**无色**文本（实测 ESC 字节数 = 0），做出来的演示会是灰的。

解法：用一次性脚本把 `openhire.console.console` 换成一个 `record=True, force_terminal=True` 的 rich Console，然后**在进程内真实调用 CLI 命令**（`typer.testing.CliRunner` 驱动 `bootstrap` / `search`），最后 `save_svg`。输出是真跑的，颜色也是 CLI 自己的 `哨兵` 主题（`src/openhire/console.py` 里的设计 token）——**没有任何手写或拼接的终端文本**，也**没有改动 `src/`**（monkeypatch 只发生在临时脚本里）。第 ① 步无 rich 输出，是把真实 `pipx install` 的 stdout 逐行原样重放。

另：rich 导出的 SVG 默认带一段从 cdnjs 拉 Fira Code 的 `@font-face`，违反「仓库内自足、无外链」，已在生成时剥掉并换成本地等宽字体栈（`Cascadia Mono / DejaVu Sans Mono / Menlo / Consolas / monospace`）。成品实测 `cdnjs` 出现 0 次、`@font-face` 出现 0 次。
