## 一、回答领导三问

### 1. 那句话不用背，已经封装好了

`add_employer` 是 0.8.13 就有的工具。助手读得到每个工具的说明，求职者说大白话就行（「帮我盯住 OKX 的招聘页」「把这个网址加进我的索引」），助手自己挑工具。0.8.14 再往前走三步，让助手主动提、让求职者一点就用：

- **服务器指令写明主动提：** 用户点名一家索引里没有的公司，助手要自己找招聘页、用 `read_board` 读，再用一句话问要不要加进本机索引并盯住（`add_employer` 加 `watch_intent`）；门户读不了（飞书、BOSS 直聘）就把门户链接给用户，有浏览器的助手主动提出替他打开。`read_board` 的结果本来就带 `add_to_my_index` 这一步。
- **五个内置提示词（MCP prompts）：** 找工作雷达 · Job radar、盯一家公司 · Track one employer、查这家公司靠不靠谱 · Check an employer、看看我的雷达 · What's new on my radar、本周新岗 · New this week。参数里有中文就出中文版，否则英文版；每条都带隐私句（简历和个人信息不进任何工具）。Claude Desktop 的「+」菜单、Claude Code 和 VS Code 的斜杠命令能看到；豆包、WorkBuddy、ChatGPT 只用工具，靠上面的指令和工具结果覆盖。
- **宣传时照抄的句子：** README 的 Quickstart 新增「What to say to it」一段，中英各几句可直接粘贴（找岗、盯一家、加进索引、问飞书门户、查公司）。文案规矩第 7 条②本来就要求带货段落把 prompt 原样写进去，以后的知乎和 LinkedIn 稿从这段取。

### 2. Xbotics 许可：稿已拟好，交本机会话发

云端的 GitHub 权限只到我们自己的仓库，所以 issue 由本机会话用 `gh` 发到 `Xbotics-Embodied-AI-club/Xbotics-Embodied-AI-Job`。内容四条：只用链接（公司名、公众号文章链接、他们标的收录日期，写明是社区收录日期、不是雇主发布日期，不复制任何文字）；处处署名并链回他们的仓库；非商用（OpenHire 不收费，没有计费代码）；随时要求撤下当天撤。一周没回复，再从 OpenHire 邮箱发到他们 README 上写的邮箱。任务书在私库 `local-session-prompt-2026-10-19.md`。

### 3. 门户链接：做了；岗位级链接：建议不做

- **门户级，0.8.14 已上线：** 新工具 `list_portals`（CLI `ohp portals`）和公开页 `docs/portals.html`（https://gzchenhao.github.io/openhire/portals.html ）。18 家读不到的公司，每家给自己的招聘页链接、不登录能看到什么、为什么不在索引里、最后核对日期，按自动驾驶 / 具身 / 大模型分组。页面由登记表生成，测试保证两者永远一致。毫末已停运，查名字时照样说明，但不进目录。
- **新发现一类盲区：** 星动纪元在索引里（读它的 Moka 页，22 条在架，最新一条 9-08 发布），但它飞书门户上挂着 19 条（10-15 本机看的），我们读不了。这类单列为「已收录、但另有一个读不到的门户」，`get_company_info` 会带 `also_posts_on`，目录页单独一节。
- **岗位级链接：** 要拿到飞书上每一条岗位的链接，得先读它的列表，而列表接口要请求签名。在我们这边用浏览器执行它的签名脚本去批量拿，就是绕过 2026-09 定下的访问控制线。人点开门户看，或者求职者自己的助手用浏览器替他打开，是人在看，不是我们在抓，这条路已经通过上面的链接和指令打开了。岗位级的一手链接改由公众号文章补（Xbotics 许可下来之后）。领导若要做岗位级抓取，需要专门裁定。
- **扩充：** 灵初、它石、星尘、乐聚、非夕、地平线、卓驭、DeepSeek 等约 30 家还没核过门户。搜索引擎基本不收录飞书的随机子域名，最可靠的办法是从官网「加入我们」点进去，交本机会话用浏览器逐家核实（不登录、不调接口、守 robots），结果回来再进登记表。

## 二、修了什么（可核对的证据）

| 项 | 原因 | 修法 | 证据 |
|---|---|---|---|
| Workday 只读到 40 条 | 列表接口第一页报真实总数，之后每页报 0，循环把 0 当真 | 只信第一个正数总数，读到不满一页为止 | 新测试：旧代码读 45 条里的 40 条，新代码 45 条；本机队列加 NVIDIA 复核 |
| Windows 改名失败 | 测试用 `with sqlite3.connect()` 只提交不关闭，改名时句柄还开着 | 测试全部改为用完即关；生产侧换文件加 5 次短重试，被占用时报出可能的占用者（Claude Desktop 里跑着的 openhire），换不过去把旧库放回 | 两条新测试（短暂占用重试成功；一直占用时报错且旧库仍可用）；本机复跑全量待确认 |
| EarlyTip 审核没有基线 | 缓存只存一份当天文件，`--fresh` 会删掉它 | `--fresh` 改为把旧副本留作 `org_events.previous.json`；新增 `--baseline`、`--expect-at-least`、`--must-include`，按 event_id 比对 | 两条新测试；任务已排进本机队列（期望 ≥ 91，点名三条 backfill id） |
| 老 SDK 上提示词 | 提示词的 `title` 参数比我们声明的 mcp 下限 1.2 新 | 不支持时不带标题注册，服务器照常启动 | 新测试 |
