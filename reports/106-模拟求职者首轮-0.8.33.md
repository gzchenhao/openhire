## 11 条发现逐条核

| 发现 | 判定 | 处理 |
|---|---|---|
| refresh_index 只给计数，不说下架的是哪几条；jobs_updated 0 与助手说的「昨天更新过」对不上 | 真 | 结果加 `delisted`（前 20 条 job_id 与标题）和 `counts_note`（jobs_updated 只数标题或正文变了的行） |
| 首次搜索前没问 IC / 管理与年限 | 真（说明不够硬） | search_jobs 说明加一句：不知道就先问再搜 |
| `ic` 把资深、高级、实习都放进来（两条） | 按设计，说明不清 | 说明写清 `ic` = intern、junior、senior、staff、unknown；应届传 ["intern","junior","unknown"] |
| 盯岗提示让用户「定时跑 radar_check」，而 radar_check 是提示词不是工具 | 真 | 改为「调用 check_watches（或用内置提示词 radar_check）」 |
| 同一会话同一长指纹第二次登记，警告「可能撞了别人的短标签」 | 真 | 长指纹改说「多半是你自己之前登记的」，只有短指纹才建议换长 |
| ghost_reason 在雇主没给日期时把「首次发现」算出的天数写成确切天数（08:35 那次） | 真 | 这种行的 ghost_reason 后面加「至少，从 OpenHire 首次看到算起」 |
| ghost_score / ghost_reason 字段名（两条） | 不改 | 协议字段名，改名会打断所有老客户端；工具说明已要求对用户只说在架天数，这次两个助手都没说「幽灵」 |
| 雇主没给日期时 datePosted 填首次发现日（两条） | 不改 | 同一行已有 date_signal、date_source、dates_in_words 三处说明；改成 null 会打断按 datePosted 筛选的提示词和老客户端，代价大于收益 |
| 没传技能时 match_quality 是 1.0 | 不改 | 所有行同为 1.0，排序就只看新鲜度，相对顺序不受影响；排序函数是锁定的纯函数 |
