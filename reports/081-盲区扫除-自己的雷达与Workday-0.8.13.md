# 081 · 盲区扫除：你自己的雷达、Workday 适配器，以及飞书那堵墙怎么绕（0.8.13）

日期：2026-10-15（云端会话）。起因有两个：知乎评论「飞书那批查不到挺可惜，智元这些恰恰是应届生最想投的，估计只能盯各家公众号和牛客的校招公告了」；领导自己找工作时发现两处盲区，一是飞书系雇主，二是我用别的办法替他找到的合适岗位 OpenHire 自己搜不出来。领导的要求是「扫除盲区，全垒打」。

## 一、盲区到底是什么

把「OpenHire 搜不到但它存在」的岗位分三类，每类的病因不同，药也不同：

| 类 | 病因 | 例子 | 能不能破 |
|---|---|---|---|
| A. 雇主不在种子表，但它的招聘系统是公开可读的 | 公开索引是人工挑的三个行业 155 家，求职者的目标雇主比这宽得多 | 领导港岗那批：UiPath（Ashby）、Airwallex（Ashby）、Lalamove（Lever）、OKX、Animoca，`read_board` 读得到，索引里没有 | **今天破了**：`add_employer` |
| B. 雇主在我们还没写适配器的系统上 | 一个系统一个适配器，没写的就读不了 | Workday（NVIDIA、Intel、AMD、Micron、宏利、汇丰这类大企业）、SuccessFactors、Taleo、iCIMS、BambooHR、Recruitee、Personio、Teamtailor；国内第一方门户（腾讯、阿里、华为、百度、美团、京东、大疆、小米、商汤、地平线） | **Workday 今天写了**，等本机实测；其余按需排队，每个一到两小时 |
| C. 雇主在访问控制的门户后面 | 列表接口要签名、要登录、要验证码 | 飞书招聘（智元、众擎、穹彻、Momenta、小马、星动纪元）、只在 BOSS 直聘、只在 LinkedIn | 直接读不行，规矩不改；**绕**的路有三条，见第三节 |

还有第四类，和数据源无关：雇主在库里、岗位也在库里，但搜索没把它端出来（标题词、技能词、岗位族分类把它滤掉了）。这一类用领导的真实目标清单做一次「召回审计」就能量出来，排在第四节。

## 二、今天破了什么（0.8.13，743 tests）

**1. 你自己的雷达：`add_employer(url)`，CLI `ohp add-employer`。** 任何一块适配器读得了的板（Greenhouse、Lever、Ashby、Moka、北森、Workable、SmartRecruiters、Workday），贴网址就进**这台电脑**的索引，并当场抓一次。进了之后它和种子表里的雇主没有区别：`search_jobs(company=...)` 有发布日期、在架天数、ghost_score；`watch_intent` 能盯；`refresh_index` 能刷；每周快照刷新时它被原样搬进新索引（`carry_over_user_state` 连 `companies` / `jobs` 一起搬，新快照没有 `user_added` 这一列就先补列）。它带 `user_added` 标记，**永远不进公开快照**：`build_snapshot` 跳过它，`install` 看到带这个标记的快照直接拒收，因为「你在看哪些公司」是你的数据，和 watches 同一条红线。`remove_employer` 移除。`read_board` 的结果现在带下一步：`add_to_my_index` 一句话，加一个预填好的 GitHub issue 链接 `suggest_for_public_index`（用户不点就什么都不发），让想进公开索引的雇主有一条路。

这一条直接回答领导的第二个盲区：以后我替他在索引外找到的雇主，一句「把 OKX 加进我的索引」就进雷达，不必再靠我手工翻。

**2. Workday 适配器。** Workday 是全球最大的企业招聘系统，大企业的 careers 站十之七八是它（HK 金融尤其）。它的列表和详情是页面自己加载的公开 JSON（`/wday/cxs/<account>/<site>/jobs`，无签名、无登录，第一次访问页面给一个普通会话 cookie），搜索引擎就是这样收录它的；按 020 的判例这是「响应体自带一切」的可解一类，不是访问控制。详情里的 `startDate` 是真实发布日，所以 Workday 行和 Greenhouse 行一样是 `ats_reported`。租户键写成 `<account>.<wdN>/<site>`（一个账号可以挂好几个站，集群名是主机的一部分）。`read_board`、板 watch、`add_employer`、种子表都认它了；`myworkdayjobs.com` 从「封闭门户」清单里删掉。**云端连不上 myworkdayjobs.com，按已知接口形状写的，17 条测试钉住；本机实测通过之前不进种子表**（和 Workable 当时一样）。

**3. Windows 的 file:// 路径修了。** 0.8.12 的三条本机测试红：`urlparse(...).path` 在 Windows 上多一个前导反斜杠，改走 `url2pathname`。

## 三、还没破的，怎么破（按价值排序）

**（一）飞书系雇主，三条绕路。**

1. **雇主授权**（已有：飞书开放平台只读 scope、自报岗位表）。零响应，留着。
2. **社区清单当发现层，公众号文章当一手源。** GitHub 上 `Xbotics-Embodied-AI-club/Xbotics-Embodied-AI-Job`（具身社区内推清单，116 KB）每条带日期、雇主、岗位名和链接，**471 条链接是公众号文章**，智元、宇树、银河通用、Momenta、星动纪元都在；`StarCycle/Awesome-Embodied-AI-Job`（Lumina，CC BY-NC 4.0）偏学术岗。公众号文章是雇主自己发的，是一手内容，不是招聘平台转手的；清单只是帮我们找到它。做法：新来源 `employer_announcement`（日期取清单记录日，链接给文章，雇主名归一到索引里的名字，`ghost_score` 不算、不标「在架」），搜索结果如实写「来自雇主公众号，经 X 清单发现，署名链接」。**前提：** Xbotics 清单没写许可证，要先去问（issue 或微信，署名 + 非商用，我们本来就不收钱）；Lumina 的 CC BY-NC 直接可用。这是回应那条评论最实在的一步：应届生最想投的那几家，用它们自己公众号里的校招公告补上。
3. **浏览器渲染读取，只在用户自己的电脑上。** `read_board --browser`：本机起一个 Playwright 浏览器打开飞书招聘页，像人一样看渲染出来的列表，不登录、不破验证码、遵守 robots.txt、被拦即停；不入公开索引、无发布日期（飞书页面不显示）。它解决的是「智元现在开着哪些岗」这个可见性问题，不解决日期。**这一条要领导裁定**：2026-09 我们判飞书 CLOSED 的理由是列表接口要签名；浏览器跑的是他们自己给每个访客的 JS，不是我们逆向签名。我的建议是允许做，但只做本机版本、只读公开页、每家每天最多一次；若飞书的 robots.txt 禁止，就不做。

**（二）更多适配器。** 先 Workday（待实测），再按领导目标清单里出现的系统排：SuccessFactors（公开搜索页是服务端渲染 HTML，带日期）、iCIMS、Taleo、BambooHR、Recruitee、Personio（有公开 XML）、Teamtailor。国内第一方门户每家一个适配器（像理想那样），优先腾讯、华为、阿里、字节、大疆、地平线，按「领导或评论区点名」排。

**（三）校招。** 牛客、海投网的公告页先探测能不能不登录读、robots 怎么写；能读就做一个校招来源。

**（四）召回审计（第四类盲区）。** 拿领导真实目标清单里的 20 到 30 个岗位，逐条查：在索引里吗？`search_jobs` 用他会用的条件能搜出来吗？搜不出的归因到哪个过滤器。这是量盲区最诚实的办法，一个下午。

## 四、本机要做的

1. 跑掉积压的本机任务队列三条（org-events 改名后重审、Tesla、Pongbot）。
2. 装 0.8.13 后，队列里新增的三条 Workday `read-board`（NVIDIA、宏利、Intel）会自动跑，结果回私库；哪条 404 就在浏览器里找该公司真实的 Workday 地址重试。
3. 用浏览器（不登录）看三样：星动纪元飞书站的 robots.txt 和列表页是否无需登录可见、页面有无日期；牛客某具身公司校招页是否无需登录；Xbotics 仓库首页有没有写许可证。记进 `local-results/blindspot-probe-2026-10-15.md`。

## 五、口径限制

- Workday 没有真机实测，接口形状来自公开资料；哪里不对本机实测后改。
- `add_employer` 用的是和每周抓取一样的请求，每块板一次；它不绕过任何访问控制，封闭门户照样拒。
- 社区清单是「发现层」，不是数据源：岗位是否还开着、发布日是哪天，它不保证，所以这类行不参与在架天数统计。
