## 一、飞书：按规矩重新评估，维持不读

在网络不受限的 Default 环境里开了一个子会话，评估了智元、加速进化、Momenta 三个飞书租户，原始记录在私库 `local-results/feishu-eval-2026-10-30.md`。三家都按同一套步骤做：
* 先读 robots.txt：三家都返回 404，没有禁止规则；
* 再打开首页：都返回 200；
* 再用我们自己的身份请求岗位列表接口：固定 OpenHire 的 UA，不带 cookie，不做任何签名，结果三家都是 **HTTP 405、空返回**，原样再试一次也一样。

响应头显示 405 来自飞书源站，不是我们的出口代理。career-ops 读得到，是因为它把客户端伪装成苹果电脑上的 Chrome，代码注释里写明这是为了过 UA 规则。这正是我们红线禁止的特征探测；换出口 IP 再试也算。**结论：飞书维持 2026-09 的判定。** 这批公司照旧走雇主授权、飞书合作和门户链接。

## 三、本机求职工作流（117 的落地）

* **插件技能** `skills/openhire-job-search/SKILL.md`：在 Claude Code 里装上 OpenHire 插件就有，四个模式是评估、改简历、面试故事库、打招呼草稿。简历是用户文件夹里的 `cv.md`，由用户自己的助手在本机读；OpenHire 的工具只拿到 job_id 或公司名；写出的文件都在用户本机的 `openhire/` 目录。
* **四个新提示词**：`evaluate_fit`、`tailor_cv`、`story_bank`、`outreach_draft`，给只认提示词的客户端用。现在一共 12 个提示词。提示词的参数只收岗位或方向，不收简历：提示词参数会传到服务器，所以测试钉住只能是 `job` 和 `focus` 两种。
* **规矩写进模板和测试**：
  * 只改写不编造；
  * 不给「别投」的结论或总分，不说假岗、僵尸岗；
  * 打招呼只起草不发送。
* README 第一屏加了一句插件说明。
