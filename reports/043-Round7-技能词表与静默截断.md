# 043 · 体验官 Round 7（小鹏覆盖审计）：两个缺陷，他的机理都说反了

日期：2026-09-20 ｜ 测试：369 passed

## 体验官的三条结论

1. 公司搜索**静默截断在 100 条**，而 `get_company_info` 报 193 → 用户只看到 52%
2. 技能过滤能搜出「公司全量列表里不存在」的岗位 → **搜索一致性 bug**
3. 智驾/具身核心技能在小鹏索引里**全部为 0**，鹏行/汇天未建索引

**三条现象全部属实。但他对第 2、3 条的机理判断都是错的，而真实机理比他说的更严重。**

## 一、静默截断（成立，P1）

实测：

```
get_company_info  active_jobs = 198
search_jobs limit=200  →  100 条，无任何提示
offset 分页          →  0..99 / 100..197，共 198 条，全部可达
```

`offset` 早就能取到全部，**但没有任何东西告诉调用方他正在看第一页。**

### 第 2 条不是一致性 bug，是同一个截断

他说 `deep-learning` 搜出的两个岗位「不在公司 100 条列表里」。逐条核验：

```
多模态视频算法应用工程师   在前100里=False   在全量198里=True
数据挖掘算法工程师        在前100里=False   在全量198里=True
```

**两条都在全量里，只是被切掉了。** 不是两个 bug，是一个 bug 的两个症状 ——
**而这让截断更严重：它已经制造出用户能亲眼看到的自相矛盾。**

### 处理

`MAX_PAGE_SIZE = 100` 提升为公开常量，两个边界层告知：

- **MCP**：请求超过上限时返回对象而非裸列表，带 `truncated`、`page_size`、`requested_limit`
  和「下一页 offset=N」的 hint，并指出 `get_company_info.active_jobs` 才是真实总数。
  **上限之内返回值形状不变**，老客户端不受影响。
- **CLI**：打印「你要了 200 条，但一次最多返回 100 条。这是第 1 页，继续翻：--offset 100」。

## 二、技能词表从未规范化（成立，而且是全库级别）

这才是第 3 条的真实原因。抽取器输出自由文本标签，**从来没有人规范化过**：

| 技能 | 搜最常见写法会漏掉 |
|---|---|
| `data analysis` | **58%** |
| `project management` | 45% |
| **`autonomous driving`** | **40%** |
| `data engineering` | 40% |
| **`computer vision`** | **38%** |
| `reinforcement learning` | 27% |

全库实测：**1,263 组标签仅因 连字符/空格/下划线 而互不相同**，涉及 2,805 个标签、13,116 行次。

**体验官把这读成「OpenHire 没有小鹏的智驾覆盖」。覆盖是有的，是查询够不着。**

### 处理

匹配时两边都做分隔符折叠，`match_quality`、`matched_skills`、以及「未知标签」判定全部同源。
最后那个尤其要紧 —— 它原本会告诉用户「你这个标签索引里根本没有」，
**而索引里全是这个标签的另一种写法**。

**只折叠分隔符，不做别的**：`c++` / `c` / `c#` 仍是三种语言，`go` / `golang` 这种同义词
留给 028 号立项，不在这里猜。存储不动，将来真做词表规范化不需要迁移。

### 我自己第一次量错了

第一版规范化函数把所有非字母数字字符都剥掉，结果 `c++`/`c`/`c#` 并成一组、
所有中文标签并成一个巨组，**把问题规模夸大了**。重算后才是上面这组干净数字。

## 三、体验官没找到的那个洞，比他找到的都大

顺着「为什么小鹏那个决策规划岗只有一个 `c++` 标签」查下去：

```
在架 16,261 条
  deepseek  7,904
  glm       5,463
  heuristic 2,894   ← 17.8% 从未经过 LLM 抽取

skills 完全为空的在架行：2,176 条 = 13.4%
```

**全库 13.4% 的岗位，任何技能搜索都找不到它们。**
小鹏那个「自动驾驶-决策规划算法技术专家」正在其中（`extraction_source=heuristic`，标签只有 `['c++']`）。

这是 CLAUDE.md 里「月度一条命令」的欠账，而**每周 CI 刷新只会让它继续长**
（CI 无 key，新行一律启发式）。已启动 `ohp extract-rebuild --backend glm` 清偿（套餐内，现金 ¥0）。

## 四、第 3 条里我确认为真、且不是我们能修的部分

小鹏这个 ATS 源确实偏「飞行汽车（汇天）+ 制造」：
标签 Top 里是 `airworthiness`(14) / `catia`(9) / `composites`(7) / `aviation`(7)，
标题里 `智能智驾类-飞行控制算法`、`智能智驾类-飞控系统设计` —— **是小鹏自己把飞行器岗位归到了「智能智驾类」**。

主线智驾的感知/预测大团队、鹏行的具身团队，**在这个 ATS 租户里就是没有**。
这不是抽取问题，是源覆盖问题，只能靠扩源解决，记入待办。

**所以体验官那句「你要找小鹏智驾/具身算法人，别拿它的结果当基准」——在扩源之前是对的。**
