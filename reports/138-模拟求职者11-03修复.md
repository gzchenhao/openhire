## 三、0.8.59 修了什么

### 两条 high

1. **薪资写了但读不出来，就说「不清楚」，不说「没写」。** `check_before_apply` 多一项 `salary_unclear`（「雇主写了薪资，但数值看起来不像年薪或月薪（可能是时薪、日薪或单位写错），原始数字在 salary_raw，请到原页面确认」）；行上新增 `salary_raw`（雇主原始的 min / max / currency / period），`salary_min` / `salary_max` 仍为 null。没写薪资的行照旧 `salary_not_stated`。
2. **职级看标题，标题没写才看正文。** `_SEN_FUNCTION_MANAGER` 加上 policy / public policy / policy design / compliance / communications / government affairs / strategy / insights / localization / documentation / knowledge / curriculum / learning / enablement / revenue operations / editorial / trust and safety / integrity 这些「管一件事不管人」的 Manager，去掉后再判，所以 Policy Design Manager 是 unknown。新函数 `seniority_for(title, description)`：标题没写级别、正文明写带人（负责…团队管理 / 带领团队 / 管理团队 / 直接下属 / direct reports / manage a team of / you will lead a team…）才标 manager；「协助团队管理」「experience leading a team is a plus」不算。`search_jobs` 的字段和筛选、`read_board`、盯岗都用它。

### medium

3. **管理岗筛选漏掉「测试策略岗」这类标题没级别的岗位**：同上，正文写「负责测试团队管理」现在进 management 筛选。
4. **「门店产品专家」不再是 senior**：标题含 店 / 导购 / 门市 / 柜台 时「专家」不算级别。
5. **应届生筛选混进 3 年岗**：seniority 只要 intern / junior / unknown 时，标题没级别但正文要求 3 年以上（`EXPERIENCED_YEARS = 3`）的行排除；请求里带 senior 等级别时不受影响。
6. **`title_exclude`**：`search_jobs`、`watch_intent` 过滤键、`ohp search --title-exclude`、`ohp watch --title-exclude`；匹配规则与 `title` 相同，盯岗每次拉取都生效。用户说「不要专家岗」现在由工具保证，不靠助手手工剔除。
7. **check_watches 首次检查改成基线的样子**：首次拉取的岗位放在 `baseline_postings`，带 `baseline_count`；`new_matches` 为空；顶层 `new_matches` 只数增量，另给 `baseline_count`；summary 两种语言都点明 baseline_postings。板盯岗同样处理。CLI `ohp check` 首次打印「首次检查：现在匹配 N 条，都是已有岗位，不是新发」。
8. **check_watches 结果瘦身**：每条只带标题、公司、地点、薪资、dates_in_words、check_before_apply、投递链接和五个协议字段（`COMPACT_KEYS`），不带 skills / requirements / ghost_reason / 排序内部字段；结果带 `fields` 说明。昨晚 26 条基线 68,000 字符、第二个雷达被截掉，现在约四分之一。
9. **`filters_applied` 全回显**：remote、remote_scope、min_salary、require_stated_salary、title_exclude 都回显；昨晚 `remote_scope=worldwide` 没回显，助手无法判断过滤有没有生效。
10. **空结果提示按实际条件算**：`no_match` 时新增 `relax`，逐个去掉一项条件各能匹配多少条；seniority 一项另报其中多少条「标题没写级别」，提示写明「seniority 里加上 unknown 就能看到」。原来固定句「required_skills 最严格」在没传 required_skills 时也会出现。
11. **地区词当地点**：location 是 APAC / EMEA / Asia / Europe / 亚太 这类地区词时，状态 `unknown_location`，提示按城市搜或用 remote_scope，不再回「条件都认得」。
12. **盯岗登记时说清看不见什么**：`what_happens_next` 在 seniority 不含 unknown 时写「标题没写级别的岗位不计入」，有 location 时写「没写城市的岗位不计入」；0 条匹配时改写成「现在没有匹配的岗位；以后出现的会在检查时列出」，英文单复数修正。
13. **`updated_at` 在行上加一句**：`dates_in_words` 多一句「雇主系统最后保存于 X，保存不等于内容有改动」（只在雇主系统报告了保存时间、且与发布日不同时出现）。助手不再把保存时间当成「最近有人改过」。
14. **校招标题挂在社招栏目**：`hire_track=campus` 而投递链接含 `/social/`（北森 zhiye 门户）时，`check_before_apply` 多一项 `campus_posting_in_social_channel`。
15. **两个工具的天数与时区对齐**：`read_board` 的 days_open 改为日历日差（与索引一致，10-13 到 11-03 是 21 天不是 20 天）；`_iso_to_dt` 把带时区的时间转成 UTC 再存（SQLite 不存时区，原来 13:43-04:00 存成 13:43 UTC，差 4 小时）。
16. **Greenhouse 远程判断**：地点文字含 Remote 优先于 Location Type 元数据（Anthropic 的板每行元数据都写 On-site，地点却写 Remote-Friendly）。
17. **check_employer 没有域名时的说明**：加一句「不要按招聘系统的账号名猜域名，猜错了查的就是别人的网站，问用户要官网地址」（中英）。
18. **工具说明**：search_jobs 写明每行约 2,000 字符、limit 不超过 10 并用 offset 翻页；写明 salary_raw / salary_unclear；seniority 一段写明正文带人的规则与 relax。watch_intent 写明 title_exclude 与 unknown 的处理。check_watches 写明 baseline_postings 与精简字段。radar_check 提示词同步。
