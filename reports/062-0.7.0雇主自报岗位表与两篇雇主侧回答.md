## 一、傻瓜式那条路：一张 Excel，一封企业邮箱的邮件

**雇主要做的全部动作：** 下载 `docs/openhire-岗位表.xlsx`（六列：职位名称、工作城市、发布日期、投递链接或投递邮箱、薪资范围、岗位描述；第二页是两分钟的填写说明），每行一个岗位，用企业邮箱发到 gdchenhao@qq.com，主题「岗位表 + 公司名」。企业邮箱发出来本身就是身份核验，不要营业执照，不要 GitHub 账号，不要任何技术人员。三个工作日内上线。

**我们这边：** 核实发件域名是该公司的 → `scripts/import_employer_roster.py` 把表转成 `employers/<slug>.json` → 在 `ats/self_reported.py` 的 `SELF_REPORTED_EMPLOYERS` 登记（名称、域名、招聘页、核实日期）→ 提交。适配器像读别家接口一样从 raw.githubusercontent.com 读这份 JSON，周一快照自动带上。

**这是我今天早些时候那句「不做自建发岗」的有条件撤回。** 早上我反对的理由是「我们会变成岗位库，假岗位从我们这里长出来」。下午做成这样之后，那个理由不成立了，因为四个条件写死在代码和测试里：

| 条件 | 代码里怎么落 |
|---|---|
| 只收企业身份核实过的雇主 | 雇主登记在 `SELF_REPORTED_EMPLOYERS`，是一个可审阅的 diff；没登记的 slug 即使有 JSON 也解析出零行 |
| 每一行都说明自己是什么 | `source = employer_self_reported`；`date_signal = self_reported`（雇主自己填的日期，ATS 的日期是系统写的改不了，这个能改，所以标出来）；`get_company_info` 带 `date_source` |
| 不靠惯性活着 | 发布日或续期日起 90 天自动下架；雇主再发一次表才续。没有日期的行不收 |
| 投递链接只信雇主自己 | 只认雇主自己域名下的 https 链接，否则把候选人送到我们核过的招聘页，并在岗位里写明投递邮箱 |

排序、ghost_score、三条隐私红线一行没动。没有 UI、没有排序影响、没有收费，它就不是岗位库，是「读雇主的系统」在雇主没有系统时的最小替代。

**代码：** `ats/self_reported.py`（适配器 + 登记表）、`ats/base.py`（`apply_url_is_trusted(extra_hosts=)`）、`service.py`（`date_signal_for`、投递链接信任）、`cli.py`（apply 同样信雇主域名）、`pipeline/ingest.py`（`source_for`）、`seed/candidates.py`（种子从登记表派生）、`scripts/import_employer_roster.py`、`scripts/make_roster_template.py`、`employers/README.md`。测试 `tests/test_self_reported.py` 9 项钉住四个条件；全量 574 通过。
