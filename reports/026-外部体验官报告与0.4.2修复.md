## 二、0.4.2 修了什么

- **版本号单一来源**：`__version__` 改为从 `importlib.metadata` 读取，物理上不可能再有第二份副本
  漂移。补了 `test_version_matches_pyproject` 做回归（源码树未安装时用 `0.0.0+dev` 哨兵跳过）。
- **`idempotentHint` 改为 False**：注解是给 agent 的契约，标成幂等会让 agent 放心重试并产生重复回执。
  **只改注解不改行为**——「重复授权是否应该产生两个回执」是产品决策，等领导定，我不擅自改语义。
- **删掉 README 的 Moka 陈旧句**。

验证（干净 venv 装 PyPI 上的 0.4.2，等同真实用户）：
```
__version__ = 0.4.2 · ohp version -> openhire 0.4.2
authorize_application  readOnly=False  idempotent=False
```

## 三、我自己的流程失误（必须记下来）

**我在测试没通过的情况下把 0.4.2 发上了 PyPI。** 原因：`pip install -e .` 因 `ohp.exe` 被占用而失败，
pytest 随即报 23 个 collection error，但我把 install→test→build→publish 串在一条命令链里，
`set -e` 捕捉不到管道尾部是 `tail` 的失败，链条继续跑完。

产物本身是好的（wheel 由 `python -m build` 从源码构建，不依赖那个坏掉的 editable 安装），
但**那是运气，不是把关**。

**改进**：发布前的测试必须单独成步、单独断言退出码，不与构建发布串在同一条命令里。

## 五、未处理的建议与我的排序意见

体验官给的 P1/P2 我没有一股脑照做，理由是它们是产品决策不是 bug 修复：

  他不知道这个设计意图，属于文档没讲清楚。
