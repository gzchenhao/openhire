# 055 · 领导亲自跑的两轮（Kimi 网页版 + 腾讯 WorkBuddy）与 0.6.8

日期：2026-09-28 · 起因：领导用一个 HR 人设（「在智驾 / 具身行业找一份招聘工作，base 香港，招聘经理 / 主管 / 总监，初创最佳」）
亲自把 OpenHire 跑了两遍：一遍在 Kimi 网页版（沙箱在国内），一遍在腾讯 WorkBuddy（领导本机）。
两个 agent 都没有给出索引本可以给出的答案。本报告把两份记录当成一轮体验测试：哪些是我们的代码缺陷（当天修完并发 0.6.8），
哪些是供给侧的事实，哪些是 agent 自己的问题。

## 一、两份记录里暴露的问题（逐条核实）

## 二、0.6.8 修了什么（全部有测试钉住，`tests/test_hr_persona_fixes.py`，560 tests 绿）

1. **`title` 过滤**：`search_jobs` / `watch_intent` / `ohp search --title`。岗位名里的词，任一命中即可；英文词锚在词首
   （`hr` 命中 HR / HRBP / HR Business Partner，不命中 Chrome），中文词是子串。只展开一组同义词：
   hr / hrbp / human resources / recruit / talent acquisition / sourcer / people ops / 人力 / 人事 / 招聘，因为 HR 正是分类表缺的那一族。
   `--company 越疆 --title 招聘` 一条命令回答「越疆有没有 HR 岗」，不用翻页。
2. **未知 `role_family` 直接拒绝**（`ERR_UNKNOWN_ROLE_FAMILY`，带合法值清单和「用 title」的指引），CLI 和 MCP 一致；watch 同样拒绝。
3. **香港是一个地方**：`Hong Kong` / `香港` / `HK` 都能到 `Hong Kong` 和 `香港·九龙区` 两种写法；`hk` 只做查询同义词、不做匹配模式
   （它是 Tashkent 的中间三个字母）。补了索引里只有一种写法的城市拼音（常州 48、沈阳 14、重庆、长沙、东莞 …）和
   新加坡 / 东京 / 伦敦 / 慕尼黑 / 台北 / 澳门；合肥到得了「安徽·包河区」（7 条）。
4. **快照下载可续传**：四次尝试，失败后用 `Range` 接着要剩下的；服务器不认 Range 就从头；正文短于 Content-Length 也算失败；404 不重试。
5. **服务器自己没拉到快照时，工具结果里说清楚**：`bootstrap_error` + 出路（`OPENHIRE_SNAPSHOT_URL` 或 `ohp bootstrap --snapshot-url <镜像或本地文件>`，
   或 `ohp bootstrap --fresh` 不经 GitHub 直接抓雇主 ATS），中英双语，明说「这是网络问题，不是市场答案」。
6. **`ghost_score` 的措辞指引**写进工具说明和 server instructions：它量的是在架时间，**不是假岗判决**；不许叫 ghost / zombie / fake / 僵尸岗，
   不许因此说「别投」；要说量到了什么（在架 1,616 天、从未重挂、ATS 不报最后触碰时间）。
7. `ohp search --company X` 默认页满了会提示还有更多、指向 `--title` / `--offset`。
8. README：腾讯 WorkBuddy 一段（配置路径、重启才加载、没有 uv 时 pip 装后指向 `ohp`）；「GitHub 不通」一段（中英）；~30 MB；
   数字按重新生成的 `docs/numbers.json`（143 家有在架岗、17,604 在架）；PyPI / Registry / mcpb 描述**不再带任何雇主数**。

## 四、没修、要领导定的

1. **国内镜像。** 续传解决的是「慢」，解决不了「不通」。第一方镜像有两条路：
   （a）魔搭 ModelScope 数据集托管（国内 CDN，最对路），但每周上传要一个魔搭 token 进 GitHub Actions secret，
   打破「工作流零密钥」；或者我每月手动传一次，镜像落后周更；
   （b）把快照切成两块 ≤ 20 MB 放到一个孤儿分支、走 jsDelivr（不用账号、不用密钥），但 jsDelivr 在国内的可达性近年时好时坏。
   第三方 gh-proxy 一类**不做内置**：镜像可以篡改索引里的投递链接，信任是用户自己的决定，所以只给 `--snapshot-url` 让用户自己选。
2. **分类表要不要加 HR 族。** 现在用 `title` 绕过去了。真加一族要改分类器、全量重抽（DeepSeek，低价时段，约 ¥6）、刷快照。建议先看 `title` 够不够用。
3. **「125 家」** 在 punkpeye 榜单那一行，PR #14921 还没合并，合并前 Kimi 这类搜索型 agent 还会引到它。
4. 蔚来的信、飞书三件套、10-03 观察期：状态不变（见 054 第八节）。

## 五、给领导的直接回答

- WorkBuddy 那边：配置没错，重启 WorkBuddy 就能看到 openhire；README 已写明。
- 「香港 + 智驾 / 具身 + HR」：索引里确实没有，这是市场事实。但「国内具身公司零 HR 岗」是 agent 翻页翻漏了，
  0.6.8 之后一句 `ohp search --title 招聘 --currency CNY` 或对助手说「搜岗位名里有招聘的」就能拿到那 16 条。
- 两个 agent 都把 1,616 天的岗叫「僵尸岗，别投」：这正是规矩 4 / 5 担心的事，从我们的字段名长出来的指控。0.6.8 把措辞指引塞进了工具说明，agent 大多会照做，但不能保证。
