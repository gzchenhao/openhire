## 二、建议：不整体搬，分工

云端会话是 Anthropic 机房里一台临时 Linux 虚拟机（约 4 核 16 GB），从 GitHub 克隆仓库开工，关掉电脑也照跑，可以同时开几个。适合写代码、跑测试、做分析、写稿；不适合任何要用领导登录态的事。

| 工作 | 云端 | 原因 / 前提 |
|---|---|---|
| 改代码、跑 600 条测试、写文档和 reports | ✅ 直接能做 | 仓库公开；Python、uv、pytest 预装；Linux 上没有 ohp.exe 文件锁的问题 |
| 用公开快照做分析（numbers.json、在架时长） | ✅ | 快照在 GitHub Release，默认网络放行 GitHub |
| 写知乎稿到 `drafts/`（私有仓库） | ✅ 要先装 GitHub App | 领导在 GitHub 给 Claude App 授权 `openhire-private` |
| Gmail 连接器 | ✅ 应该可以 | 连接器流量走 Anthropic 服务器，不受虚拟机网络限制 |
| 抓雇主接口、DeepSeek 精抽 | ⚠️ 要配网络 | 默认「Trusted」只放行软件源和 GitHub；要改「Custom」加域名（清单见第四节）；DeepSeek key 用「网络密钥」存，会话里看不到 key |
| `check_employer` / 雇主身份核验 | ⚠️ 要「Full」 | RDAP 会跳转到各注册局、还要访问任意公司官网，白名单列不全 |
| **发 PyPI** | ❌ 现在不行 | 文档写明网络密钥**永远不会**附到 pypi.org 的请求上，token 只能放明文环境变量，违反我们「key 不出密码管理器」的规矩。出路见第三节 |
| 知乎、X、即刻、CNB、claude.ai 目录的网页操作 | ❌ | 都靠领导电脑上浏览器的登录态 |
| Claude Desktop 里实机测 MCP、双击 mcpb | ❌ | Windows 本机才有 |
| 本机记忆（`~/.claude/projects/.../memory`） | ❌ 不带过去 | 仓库里的 CLAUDE.md 会带过去，主要规矩都在那里；记忆我镜像进私有仓库即可 |

## 三、最值得用这笔额度做的事

1. **PyPI 改「可信发布」（Trusted Publishing）**。GitHub Actions 用 OIDC 直接发 PyPI，零密钥，和 MCP Registry 现在的做法一样。做完以后推一个 tag，PyPI、mcpb、GitHub Release 全自动，云端会话和本机都能发版，本机 `.pypirc` 里的 token 可以作废。领导要做的只有一次：登录 PyPI，在 openhire 项目的 Publishing 页加一个可信发布者（仓库 `gzchenhao/openhire`、工作流文件名我给）。
2. **0.8.1**：`check_employer` 说明里写明「助手已有天眼查工具就直接补工商登记」（上次答应的）。
3. **10-12 快照出来后**：重算 numbers.json，把三篇老知乎回答的数字更新稿写好，发布仍回本机。
4. **种子扩充调研**：智驾 / 具身 / AI 基础设施里还没收录的公司逐家看招聘系统，开 Custom 网络后在云端并行跑。

注意一条边界：**被某个站点拦过的，不许换到云端再抓**（云端是另一个 IP，等于「换 IP 再试」，违反禁止特征探测）。蔚来照旧停用。每周大抓取本来就在 GitHub Actions 上跑，云端会话不需要承担它。
