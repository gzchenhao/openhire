## P0-① 全文最硬的数字没有出处（最严重，已修）

幽灵岗位长文里写着：「多家招聘平台的抽样数据显示，线上招聘信息里大概有五分之一是幽灵岗位。」

**在一篇以「我不是猜的，是查过的」立信的文章里，唯一那个硬数字是凭印象写的。**

没有去补来源，**换成我们自己能复核的数**，并在文中挂更正说明：

```
挂超 90 天  约 43%      挂超 180 天  约 22%
挂超一年    约 9%       中位          75 天
```

「超过半年」那 22% 和坊间「五分之一」数量级对得上，但**这是我们自己量的，读者能复现**。
同段落把边界写死：**量得到「挂了多久」，量不到「对方还想不想招」**，三种解释（没打算招 /
真招不到 / 常青岗）数据上分不开。

## P1-① numbers.json：根治数字漂移

所有文章写「139 家」，`companies` 表 140 行，**连续两轮被抓**。

这从来不是数错了，**是两个不同的问题共用了一个标签**。新增 `ohp numbers`：

```json
{ "companies_in_index": 140, "employers_with_live_postings": 139,
  "live_postings": 15966, "median_days_open": 75,
  "pct_open_over_90d": 43.3, "pct_open_over_180d": 22.3, "pct_open_over_365d": 8.8 }
```

**每个字段名都说清它数的是什么。** 有测试断言两个计数都存在、且后者不大于前者。

**它当场抓到我自己一小时前的漏**：文章写 22.4%，管道算 22.3%。于是把文章改成取整 +
标注实测日期，周更刷新就不会让它回溯变错。

`CLAUDE.md` 新增两条硬规矩：数字只准引用 `docs/numbers.json`、零破折号。

## P0-③ 人设收束（领导批准）

一个月三张名片：「我不是程序员，是个 PM」/「我做过几年猎头 FA」/「我做过几年深科技猎头」。

**批准的方案**：主叙事 =「深科技猎头，覆盖智驾与具身」；
「用 AI 结对写代码」只作**方法说明**，不作身份。

- v0.2 文：「我不是程序员，是个 PM」→「我是做深科技猎头的，不是程序员，代码全程用 Claude Code 结对写出来」
- 幽灵文：「我做过几年猎头 FA」→「我做过几年深科技猎头，主要覆盖智驾和具身」
- 具身文：本来就是主叙事，未动
- README 英文版同步
- 规则写进 `CLAUDE.md`

**BOSS 回答那篇没改。** 它写的是「猎头 FA」，与主叙事同职业、非冲突项
（体验官指的真冲突是 PM 那张，已拔掉）；而知乎**回答没有草稿 API**，只能走 UI 编辑器，
记忆 `zhihu-editor-automation` 明确记着编辑器拒绝自动化注入。
**这是我们流量最好的一篇（14 赞同），不为 5 个字的标签差异冒险。**
