## 四、发版路上撞到的：mcpb 的第五处版本号

`.mcpb` 里跑的是 `uv run --directory <bundle> src/server.py`，**真正装哪个版本由 `mcpb/pyproject.toml` 的 `dependencies = ["openhire==X"]` 决定，manifest 里的版本号只是标签。**

打开 `dist/openhire-0.6.1.mcpb` 看：标签 0.6.1，依赖钉 **0.5.1**。

**所以昨天 046 里写的「Release 含 mcpb ✅」是真的，但双击安装的用户装到的一直是 0.5.1。** 从 0.6.0 起每一个 mcpb 都是这样。讽刺的是，这反而让 mcpb 用户躲过了 0.6.0 的首搜必崩（0.5.1 不认识新列），但他们也没拿到任何一个修复。

已修：钉到 `openhire==0.6.2`；新增 `tests/test_release.py` 把**五处**版本号（`pyproject` / `server.json` ×2 / `mcpb/manifest.json` / `mcpb/pyproject.toml` / README 文件名）钉死到 `pyproject.toml`；CLAUDE.md 铁律改成五处。

另一个小坑：Registry 对 `description` 限 100 字符，第一版 213 字被 422 拒掉，v0.6.2 的 tag 推上去 Registry 什么都没发。缩到 96 字、加测试、`workflow_dispatch` 手动重跑成功。
