# 027 · 从 agent 视角重看「同岗多城市」：role_group + 分页（v0.5.0）

日期：2026-09-12

## 背景

领导问了一个把问题性质翻转的问题：同一岗位铺多个城市，**站在人类 AI agent 的用户体验来说**是什么情况，
而不是人类用户。

原先我把它归为「呈现问题」，优先级不高。按 agent 视角重估后，结论是它对 agent **比对人类更严重**，
因为人类有直觉的补救动作，agent 没有。

## 一、先量化（不空谈）

同一查询（`remote=True, role_family=engineering`）在不同 limit 下的同 (公司,标题) 重复率：

| limit | 实得 | 去重后 | 浪费 |
|------:|-----:|-------:|-----:|
| 5 | 5 | 4 | 1 (20%) |
| 10 | 10 | 8 | 2 (20%) |
| 20 | 20 | 16 | 4 (20%) ≈ 890 tokens |
| 50 | 50 | 40 | 10 (20%) |

**稳定的 20% 税**，不随 limit 变化。全库 15,963 条在架岗位里，**2,345 条是同 (公司,标题) 冗余**
（MongoDB 一个 AE 岗铺 22 个城市，Databricks 一个 FDE 岗 15 个）。

我原先担心的「一屏全是同一个岗位」**实测不会发生** —— 排序把它们打散了。所以这是持续小额损耗，不是灾难。

## 二、为什么对 agent 更糟（四点）

1. **`limit` 对 agent 是预算不是屏幕。** 人说「看 5 个」是「先看 5 个」；agent 说 `limit=20`
   是「我要基于这 20 个做判断」。它以为拿到 20 个机会，实际 16 个，而且无人告知。
2. **我们当时没有分页。** 这条最要命。人类发现重复可以换个筛法；agent 想要「再来 20 个不一样的」，
   API 里根本没有这个动作 —— 无 cursor 无 offset，它被卡死。
3. **context 是 agent 唯一真正稀缺的资源。** 一次查询 890 tokens，一个会话搜五六次就是数千 tokens
   换不来新信息。
4. **payload 里没有任何字段说明「这是同一岗位的不同城市」。** 它只能靠字符串相等去猜，
   而让 agent 去猜正是本协议存在意义的反面。

## 三、方案：不去重，打标

去重是替 agent 做决定，而且会丢信息 —— Dublin 与 Austin 对有签证限制的候选人是两件事，
每条各有自己的 `apply_channel`（五个协议字段之一）。

这与 `service.py` 自己的注释一致：**服务端只做硬过滤 + 固定排序，精确判断留给持有用户上下文的客户端。**

### 做了什么

- **`role_group`**：`(company_id, 大小写空白归一后的 title)` 的稳定哈希，形如 `rg_25ebdea6`。
  在 `job_posting()` 里**计算**而非存储 —— 无需迁移，对已在野外的快照立即生效。
- **`offset`**：排序后列表上的普通跳过，贯通 service / MCP 工具 / CLI。
  **返回结构完全未变**，老客户端不受影响（0.3.0 那次破坏教过我们代价）。
- **`search_jobs` docstring 写明两个用法** —— 因为 docstring 才是 agent 真正会读的东西。

### 刻意没做：城市名剥离

| 归一化方式 | 可合并冗余行 |
|---|---|
| 精确 (公司,标题) | 2,345 |
| 再剥标题尾部城市 | 2,572（仅 +227，+1.4%） |

**91% 的收益来自精确匹配。** 剥城市要引入启发式，可能把真正不同的岗位错误合并。
**消费者是机器时，可预测优于聪明。**

## 四、验收证据

```
分页：limit=5 offset=0 与 offset=5 两页 job_id 无交集 ✓
折叠：20 条里 role_group 唯一值 16 个，4 组有重复；
      rg_25ebdea6 x2 = MongoDB 同一岗位的 Austin/NY/SF/Seattle 与 Dublin 两行，
      job_id 与 apply_channel 各不相同（未被折叠，符合设计）
续取：offset=20 再拿 20 条，其中 14 个是全新 role_group
```

- 新增 5 个测试（`tests/test_role_group_and_paging.py`），覆盖：同岗共享分组键且行不被折叠、
  不同岗位分组键不同、大小写/空白归一但不跨公司、分页无重叠且能探到末尾、offset 越界与负数被钳制。
- **262 tests green**；隐私 + 排序红线 20 条单独复跑通过；`rank_score` 签名未动。
- PyPI 上的 0.5.0 wheel 实测含 `role_group` 与 `offset`（含 MCP 工具层）。

## 五、过程中的两个教训

1. **补丁脚本把 `\x00` 写成了真的 null 字节**进源码，Python 连解析都过不了；改用 ` :: ` 分隔符。
   另外 Python 3.11 的 f-string 表达式内不允许反斜杠，归一化要拆到表达式外。
2. **`ohp.exe` 文件锁第三次咬人** —— 这次终于写进 CLAUDE.md：改 venv 前先在 Claude Desktop 里停掉
   openhire。中招后 `pip install -e . --no-deps` 能救回来，但**必须重跑 pytest 确认，不能靠推断**
   （本轮那 24 个报错是环境坏了不是代码坏了，重装后 262 全绿）。
