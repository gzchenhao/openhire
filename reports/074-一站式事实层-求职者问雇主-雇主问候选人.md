# 074 · 把「数据做市商」做到底：求职者问雇主的 15 件事、雇主问候选人的 6 件事，OpenHire 能给什么、怎么给（2026-10-12，云端会话）

领导 10-12 的要求：既然是数据做市商，就把这条数据承载到底。求职者想知道：雇主是不是骗子、主营产品、卖得怎样、人数、融资、增长潜力（薪酬涨幅，最起码别倒闭）、双休否、上班与午休时间、五险一金基数与比例、福利津贴、加班多不多、卷不卷、办公城市与位置。雇主想知道：候选人年龄、学历、核心技能、量产经验、顶会论文、跳槽频率、实力。要 OpenHire 一站式提供，花 token 的用户自己掏，我们把 API 接好，给他们一个离不开 OpenHire 的理由。

本报告按「能拿到的事实、只能取雇主自己写的、拿不到也不该编的」三类逐项回答，雇主侧按红线一单独处理，最后是路线图。原则不变：给事实与出处，不给判决，不做预测。

## 一、求职者问雇主：15 件事分三类

| 问题 | 现在 | 能从哪拿（来源、许可） | 做法 |
|---|---|---|---|
| 1 是不是骗子 | `check_employer` 七项加制裁比对 | 已有；香港公司註冊處、OpenSanctions 在路线图 | 不变 |
| 2 主营产品 | 无 | 登记经营范围（天眼查，用户自己的 key）；官网首页标题与描述（已有的一次普通 GET）；上市公司公告（巨潮、披露易、SEC，免费公开） | 进 `company_facts` |
| 3 卖得怎样 | 无 | 上市公司：年报营收（免费公告）；非上市：**拿不到，不编**；融资事件作为替代事实（org_events，12 月后） | 上市取，非上市写「无公开来源」 |
| 4 人数 | 索引里的在架岗位数与城市分布 | 天眼查参保人数（用户 key）；LinkedIn 人数不可抓 | 进 `company_facts` |
| 5 融资规模 | 无 | 天眼查（用户 key）；org_events；Crunchbase（用户 key，按它的署名规则） | 进 `company_facts` |
| 6 增长潜力、薪酬涨幅、别倒闭 | 「已停止运营」登记（毫末案例） | **不做预测。** 给事实信号：经营异常与行政处罚（天眼查）、停止运营登记、岗位数时间序列（路线图「招聘速度」）、重挂记录；薪酬涨幅没有任何公开来源 | 事实进 `company_facts`，涨幅进「面试要问的问题」 |
| 7 到 11 双休、工时、午休、五险一金基数与比例、津贴 | 无 | **只取雇主在 JD 里写的原句**：双休、大小周、965、弹性、午休时长、五险一金、六险一金、补充医疗、年终奖、餐补房补交通补。基数与比例几乎没人写 | 新字段 `stated_in_jd`：原句加结构化字段，没写就 null，**缺席不等于没有**；基数比例进面试问题 |
| 12 到 13 加班多不多、卷不卷 | 无 | 这不是事实是感受。员工评价站（看准、Glassdoor、脉脉）条款禁抓、内容是匿名观点、无法核对，**不采集**。JD 里若有「能接受加班」「弹性工作」照录 | 进 `stated_in_jd` 和面试问题 |
| 14 到 15 办公城市与位置 | 每条岗位有 location | 聚合成 `office_cities`（已能算）；具体地址只取 JD 写的；登记地址来自天眼查但**登记地不等于办公地**，要标明 | 进 `company_facts` |

三个新东西：

1. **`company_facts`**：把 `check_employer`、`get_company_info`、天眼查几项、上市公告、org_events 汇成一张事实单，每项带来源、时间、五种状态（和 0.8.0 的查证清单同一套语义）。
2. **`stated_in_jd`**：从 JD 原文抽「雇主自己写的工作条件」，先用词表启发式（免费、离线、CI 可跑），可选用户自己的 DeepSeek key 精抽；每个字段带原句。这是 0.6.6「不从光秃秃的标题里抽技能」那条纪律的延伸：没写的不抽。
3. **`questions_to_ask`**：对拿不到的那些（涨幅、基数比例、加班、卷），不编答案，生成面试时该问 HR 的原话和「什么样的回答算清楚」。这是猎头功力的产品化，零数据风险，也是别家平台给不了的。

## 二、雇主问候选人：候选人数据一个字节不经服务端，做法是「求职者带着事实来」

红线一不动摇。能做的：

1. **候选人事实单（schema）**：学历、核心技能、量产经历（项目、车型或产品、阶段）、论文（DOI 列表）、任职时间线。由求职者的 agent 在本机填，本人授权后随那一次投递送达雇主（就是「按投递付费」的那一次），OpenHire 不存。
2. **雇主的 agent 本机核验**：论文 DOI 用 OpenAlex（免费、无 key）核真伪与作者位次；任职时间线自然显示跳槽频率；GitHub 公开作品自己看。核验工具只在雇主本机跑，输入是雇主已经合法持有的投递材料，不经我们。
3. **「实力如何」不评分**：OpenHire 给事实不给判决。雇主的 agent 用公开的 resume-screening 规则（先判赛道与细分职能，再看匹配，禁止关键词命中）自己打分，和领导的猎头台一样。
4. **年龄不进事实单**：内地《就业促进法》禁止就业歧视，香港平机会对年龄歧视有指引；年龄由雇主依法在面试里问，不由我们传。

## 三、谁掏钱：BYOK，我们接 API 不经手钱

天眼查已经是这个模式（用户自己的 key，我们看不到他查谁）。扩展同理：免费源优先（OpenAlex、巨潮、披露易、SEC EDGAR、OpenCorporates、RDAP、互联网档案馆、OFAC），付费源用用户自己的 key（天眼查、Crunchbase、DeepSeek 精抽）。每个源在隐私说明 §3 里写明向谁发什么。

## 四、离不开的理由

不是数据扣在手里，是四件别人给不了的事同时成立：中立（不收曝光费不卖排序）、诚实（每个数字有出处、不做判决）、一站式（查证、事实、JD 条件、面试问题、盯岗、投递一条线）、数据在自己机器。信任是护城河。
