# 105 Claude API 赠送额度：每晚自动跑「模拟求职者」测试

日期：2026-10-29（云端会话）。不发版（只加脚本和测试）。

## 背景

领导的 Claude Console 有一笔 US$100 赠送额度（10-22 授予，**11-11 过期**），余 US$96.22，可用于 API、批处理、Agent SDK。领导要求「用最不用我操心的方式用，电脑长期开机，要抓紧花出去」。

用途选在**自动体验测试**，不用来替代 DeepSeek 精抽：
- 0.8.27 的首发盯岗缺陷过了全部测试和每日体检，是真人用户（赵杭铨）发现的（reports/098）。
- 9 月的人设体验测试（reports/051、054）每轮抓出 10 条以上缺陷，但都是手工组织。
- 精抽有 DeepSeek 月度一条命令，不急；接 Claude 进精抽流水线要改 rebuild，额度到期前不值得。

## 做了什么

1. `scripts/persona_test.py`：
   - 10 个人设：北京应届具身算法、香港 HR、湾区资深感知 IC 加盯岗、上海测试经理（管理岗）、上海产品经理（不带人，测「产品经理不算管理岗」）、查两家公司（一家可能不存在）、深圳嵌入式盯岗后马上检查、完全新手、读 Anthropic 招聘板、要把简历和手机号交给 OpenHire 投递（隐私测试，手机号是假的）。
   - 每个人设一段对话：Claude Opus 5.5 当用户的 AI 助手，经 Messages API 的 MCP connector 连托管端点 `https://openhire-vlny.onrender.com/mcp`；Claude Sonnet 5.5 扮演求职者，按人设回答助手的追问，最多 3 轮；Claude Opus 5.5 按 OpenHire 的十条承诺（数据来源、日期、在架口径、级别、首轮五条六栏、盯岗说明、空结果说明、查公司是清单不是判断、隐私、措辞）读完整记录，打分并列出发现（严重度、对应承诺、证据、建议）。
   - 每次响应按价目表计费，累计账本放在输出目录；单次超 `--budget-usd` 不再开新人设，累计到 `--total-cap`（默认 US$80）拒绝再跑，退出码 2。
   - key 用单独的名字 `OPENHIRE_PERSONA_API_KEY`，不与精抽的 `ANTHROPIC_API_KEY` 混用（`auto` 后端不会拿去抽取），测试钉住。
2. `tests/test_persona_script.py` 8 条：假客户端跑通一整段对话（MCP 参数、工具结果截断、模拟用户回一轮、评分）、pause_turn 续跑、四种 token 计费、累计上限拒跑、dry-run 不要 key、报告按严重度排序。全量 1003 通过。
3. 本机待办第 29 条：每晚到 11-10 跑一次（第一晚先小跑两个人设），结果写 `drafts/local-results/persona-runs/`；第 30 条：11-11 从 `.env` 删掉 key。
4. 云端定时任务「模拟求职者测试日读（到 11-11）」每天 10:37（香港时间）读昨晚的 report.md，逐条核真伪，真问题当天修并发版，写汇报；11-12 自动提醒停用。
