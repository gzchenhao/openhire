## 六、CNB 镜像仓库（领导 2026-09-28 下午拍板「做」）

- 镜像地址：**https://cnb.cool/gzchenhao/openhire** （组织 `gzchenhao`，和 GitHub 账号同名）。首轮同步已完成：main = GitHub 的 c9c74a4，206 次提交，21 个 tag（v0.1.0 到 v0.6.8）全部在，README 正常渲染。
- 机制：GitHub 主仓库里加了两个文件，`.cnb.yml`（CNB 流水线：每 6 小时从 GitHub 匿名拉取 main 和全部 tag，用流水线自带的临时令牌 `CNB_TOKEN` 强推进镜像；GitHub Actions 不读它）和 `.cnb/web_trigger.yml`（CNB 分支页上的「从 GitHub 同步」按钮，立即同步一次）。两个文件放在 GitHub 里，是为了镜像同步后它们自己不会消失。**GitHub 侧零密钥，CNB 侧也没有手工创建任何令牌。**
- 踩过的坑，下次直接照做：
  1. CNB 建仓库必须先建组织，建组织要**实名认证**（微信扫码，只能领导做）。组织名 `openhire` 被 CNB 按域名保护（要验证 openhire.com 所有权），改用 `gzchenhao`。
  2. CNB 的新建文件编辑器是 Monaco，逐字输入和粘贴都会被 YAML 自动缩进搞成阶梯；内置浏览器的剪贴板粘贴也进不去。解法：把引导用的 `.cnb.yml` 写成**单行 JSON**（YAML 是 JSON 的超集，一行没有换行就没有缩进问题）敲进去，只带一个 `push` 事件，提交即触发首轮同步，同步完成后被 GitHub 版本覆盖。
  3. CNB 表单是 React 受控组件，工具直填不生效，要么真实键入，要么原生 setter + input 事件。
- 顺手发现的一个可能性：CNB 是腾讯托管、国内可达，有「制品库」和 release。国内快照镜像那条待定项，可以考虑让 CNB 的定时流水线把 GitHub Release 的 `openhire-index.db.gz` 搬到 CNB 上；没验证，只记一笔。


补记（同日 15:56）：**定时任务只在真人推送时登记**。流水线自己用 `CNB_TOKEN` 强推的那次没有登记（定时任务页「暂无数据」），
用网页编辑器给 `.cnb.yml` 加了一行注释、以领导身份提交后才出现「crontab: 0 */6 * * *」。GitHub 上同步加了同一行，两边文件逐字节一致。
