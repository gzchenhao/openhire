# 056 · 腾讯云开发者 MCP 广场能不能上架（2026-09-28）

领导问：OpenHire 能否想办法上架 https://cloud.tencent.com/developer/mcp 。025（09-11）的结论是「不可做」，依据是官方文档一句「第三方 MCP 产品暂不提供上架与更新服务」。这次把页面、文档、接口和背后的提交仓库都翻了一遍，结论改了：**有一条有先例的路，但入口不在广场页面上，而且没人回话。**

## 一、核实到的事实

| 项 | 事实 | 出处 |
|---|---|---|
| 官方政策 | 文档 2026-08-13 版仍写「针对第三方 MCP 产品，目前暂不提供上架与更新服务」 | cloud.tencent.com/document/product/1212/123193 |
| 广场规模 | 1,050 条，12 个分类；第三方条目全部带 GitHub 链接和机翻 README | 广场首页 |
| 页面入口 | 没有任何「提交 / 上架 / 入驻」按钮；只有页脚「联系我们」`cloudcommunity@tencent.com`、「建议反馈」表单、一个微信群二维码「MCP开发者交流站」 | 页面 DOM |
| 真正的提交仓库 | **cnb.cool/codebuddy/mcp-market**（「腾讯云代码助手 MCP 市场」，MIT）：README 写明「开发者可在此提交自己的 MCP 服务器」，用 issue 模板 `[Server Submission]` 收六个字段 | 仓库 README 与 issue 列表 |
| 管道是否活着 | 20 条 issue（16 开 4 关），**没有一条有维护者回复**。但用广场搜索接口（`/developer/api/mcp/list-by-search`）核对：DemoWay 2025-05-15 提 issue、2025-07-25 出现在广场；「有活 · B端招工 MCP」2026-06-30 收录。反例：HowToCook、PromptX、EarthquakeInfoPy 提了没收 | 接口返回的 `createdAt` |
| 仓库地址要求 | README 写「CNB 仓库地址」，DemoWay 用 GitHub 地址也收了 | issue #8 |
| 登录 | CNB 只有微信登录；广场的反馈表单要腾讯云账号 | 页面 |
| 同类竞品 | 广场里求职相关只有 Google Jobs 搜索服务器（209 阅读）、LinkedIn 连接器、有活·B端招工；**没有直连雇主 ATS 的求职 MCP** | 搜索接口 |
| 广场与 CodeBuddy 市场 | 广场文档的配置示例全用 `codebuddy_mcp_settings.json`，云托管生成的 SSE 地址也是给 CodeBuddy 配的；提交仓库归 codebuddy 组织。两者是一套目录 | 文档 + 仓库归属 |
| 元器插件市场 | 用户可自配 MCP 插件，但要一个公网 URL（SSE / streamable-http）；「精选」由腾讯挑 | yuanqi.tencent.com 指南 |

## 二、怎么做（材料已备好：`drafts/tencent-mcp-listing.md`）

1. **主路：CNB issue。** 领导在内置浏览器打开 https://cnb.cool/codebuddy/mcp-market ，点「微信登录」扫码，告诉我一声，我照模板把六个字段填好提交（字段内容已写在 drafts 里，数字取自当天 `numbers.json`：143 家有在架岗、17,604 在架）。
2. **并行：邮件** `cloudcommunity@tencent.com`，正文已写好，领导从自己邮箱发；附上 issue 链接。
3. **可选：CNB 镜像仓库。** 用 CNB 的「导入仓库」从 GitHub 拉并定时同步，GitHub 侧不加密钥；只是加分，不是门槛。
4. **暂不做：云托管模式 / 元器插件。** 技术现成（streamable-http + Dockerfile），但托管意味着搜索经过腾讯的服务器，和「跑在你自己机器上」要分开讲。等收录再议。

## 三、预期

- 有先例的等待期是两个多月（DemoWay），且没有任何回音机制。提了就当种下，不追。
- 收录后的价值：CodeBuddy / WorkBuddy 的 MCP 市场里能一键装，这正是 055 里 WorkBuddy 找不到我们、只能手填 JSON 的那个缺口。
