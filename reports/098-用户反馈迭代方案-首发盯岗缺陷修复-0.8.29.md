## 二、今天修掉的缺陷（0.8.29）

**现象（他的原话）：** 「随后设置盯岗又报错，重启后恢复。」

**原因：** 服务器第一次启动的顺序是：先在空索引文件上建全部表（init_db），再由后台线程下载公开快照、把整个文件换掉。公开快照按隐私红线只含 companies 和 jobs 两张表，于是换完文件之后，watches 和 applications 两张表不存在；这个会话里任何 `watch_intent`、`authorize_application` 都报 `no such table: watches`，直到重启时 init_db 再跑一次才补建。

**影响范围比他遇到的大：**

- 每一个走 MCP 路径的新用户，第一个会话里设盯岗都会报错（搜索不受影响，因为搜索只读 jobs）。
- 托管端点（ChatGPT 连接器用的那个）每次冷启动都重新下载快照（Render 免费档没有持久盘），所以它上面的盯岗**从来没有成功过**，而部署检查和每日体检只查 initialize 和 tools/list，一直是绿的。

**修法：**

1. 下载安装完立刻 init_db（`mcp_server._do_bootstrap`）。
2. 新测试 `tests/test_first_run_watch.py`：按真实顺序建空库、装快照、不重启就调 search_jobs、watch_intent、check_watches、authorize_application。把修复撤掉跑一次，测试红（`1 failed`）；修复在，绿。
3. 部署与每日体检脚本 `scripts/hosted_mcp_check.py` 加一次 watch_intent 和 check_watches 往返（一个不会匹配任何岗位的临时条件，一行小记录），以后托管端点这一项坏了，工作流会红。

**证据：**

- 全量测试 893 passed（原 892，加 1）。
- 本地按托管模式冷启动一个端点（空库，从本地快照文件引导），/healthz 就绪后跑体检脚本：initialize 与 tools/list 通过，`watch_intent and check_watches round trip ok (w_8c18)`。
- 发版核对见文末补记。

## 三、六条反馈逐条

### 第 1 条：给普通求职者一个网页搜索入口

**现状：** 没有网页搜索。零安装的路径只有 ChatGPT 连接器（付费档、开发者模式）；豆包要本机跑一个进程；Claude Desktop 有双击安装的 mcpb；Cursor 有一键；他用的 **VS Code 加 Copilot，README 里一个字都没有**。

**判断：现在不做公开的网页搜索页。** 三个原因：

1. 合规。面向公众、可检索的岗位列表页，是《网络招聘服务管理规定》里最典型的「网络招聘服务」形态。OpenHire 现在的形态（给用户自己的 AI 助手用的数据源，无界面、无账号）是否落入这条，已经排进 12 月律师清单（EarlyTip 线 10-21 提出，`reports/088`）。先做网页，等于替律师把答案往坏的方向定了。
2. 产品。他最想要的两样「每个岗位为什么适合我、哪里可能不匹配」，只有拿着他的简历和要求的助手能做，这正是简历不出电脑的设计；网页版做不到这两样，会是一个更差的 OpenHire。
3. EarlyTip 的约定。「查公司」页挂在托管站点上，这个站点一旦变成岗位列表站，EarlyTip 对「个人备案站点给招聘工具导流」的顾虑就回来了。

**做法：把「第一次接入」的门槛单独解决，不放岗位：**

- 连接向导页 `/connect`（docs 与托管各一份，和清单页一样钉住一致）：先选助手（ChatGPT、Claude、豆包、DeepSeek 经 Cherry Studio、Cursor、腾讯 WorkBuddy、VS Code Copilot），只显示那一种的步骤和一键复制的「装机加提问」合并版 prompt；按操作系统给 uv 安装行；页面不含任何岗位，不改变站点性质。
- README「Works with」加 VS Code（Copilot）：`.vscode/mcp.json` 片段和一键安装链接。
- 托管首页把 ChatGPT 这条「不用装任何东西」的路径放到最前面给非开发者。

**排期：** 向导页与 README 进 0.8.30。网页搜索页待领导定，建议 12 月律师意见后再议。

### 第 2 条：先看到适合我的岗位（Zoox 的 perception 第一条是 Senior Manager）

**现状：** 排序是 0.7 × 技能匹配 + 0.3 × 新鲜度（红线 2，签名锁死），匹配只看技能标签，所以同样匹配的岗位按发布日期排。索引里**没有「个人贡献者 / 带团队」「年限」字段**，助手只能用标题子串筛。

10-26 快照复现：`company=zoox, title=["perception"]` 的第一条就是 Senior Manager, Perception Data（35 天，最新），第五条是 Director, Perception（366 天）。全库 20,196 条在架里，标题带 director / VP / 总监 / 负责人 的 918 条（4.5%）；带 manager / 经理 / lead 的 4,949 条（24.5%），其中 2,281 条是产品、项目、客户经理这类不带人的岗。

**做法：**

a. 每行加 `seniority`：intern | junior | mid | senior | staff | manager | director | unknown，由标题的免费规则在读取时算出，不改快照、不花钱；产品 / 项目 / 客户经理归个人贡献者。`search_jobs` 和 `watch_intent` 加 `seniority` 过滤（可多选），规则同 role_family：只排除确定是别的级别的行，unknown 保留。这是硬过滤，不是排序参数，排序函数不动。
b. 服务器指令、job_radar 和 job_checklist 提示词：用户没说清的，开搜前问一次「个人贡献者还是带团队、大概几年」，再带 seniority 搜。
c. 「为什么适合、哪里不匹配」是助手的活，我们给材料：已有的 `matched_skills`，加第 6 条的 `check_before_apply`。

**排期：** 0.8.30。

### 第 3 条：日期和分数要翻译成普通用户的话（理想的例子）

**现状：** 每行已有 datePosted、days_open、date_signal、verified_at、updated_at、ghost_score、ghost_reason，语义都写在工具说明里，但助手常把字段名直接念给用户。10-26 快照：775 条（3.8%）没有雇主自己的发布日期，全部是理想汽车（它的接口不给日期），这些行的 datePosted 是本工具首次发现日。

**做法：**

- 每行加 `dates_in_words`（中英各一句，助手可以原样说）：
  - 有雇主日期：「雇主发布日期 2026-09-23，在架 35 天；最近核验 2026-10-26，雇主系统当天仍返回这条岗位。」
  - 无雇主日期：「雇主系统没有提供发布日期；本工具首次发现日期 2026-09-23，在架至少 35 天；最近核验 2026-10-26。」
  - 在架超过 90 天再加一句：「在架较久，投递前建议先确认仍在招。」不出现「假岗」「不招了」。
- 加 `date_source`：employer_ats | employer_self_reported | index_first_seen，比现在的 date_signal 直白；旧字段保留，老客户端不受影响。
- ghost_score 是协议字段，名字不改；工具说明再压一次「分数不是靠谱度」。

**排期：** 0.8.30。

### 第 4 条：搜不到或报错时，用户要一个明确的下一步

**现状，四种情况分别怎么表现：**

1. 索引正在下载：工具最多等 180 秒，没等到就按空索引回答，提示是「本机没有索引，跑 ohp bootstrap」。**这是错的**，其实正在下载，再等一会儿就好。
2. 下载失败：有 `bootstrap_error` 和出路（镜像、手动指定快照、直接抓），对。
3. 没有匹配：有 hint、unknown_skills、suggestions，对。
4. 盯岗报错：今天修了（第二节）。

他遇到的「自动下载索引遇到环境兼容问题」没有报错原文，猜不出是哪一种（`ohp doctor` 能分辨 uv 缺失、索引空、配置没启用三种）。

**做法：**

- 每个工具结果带 `index_status`：ready | preparing（下载中，带已等待秒数和「稍后再搜一次，这不是没有岗位」）| unavailable（下载失败，带一条下一步）。下载中不再冒充「没索引」。
- 搜索空结果的 hint 固定三种开头：「正在准备岗位数据」「这次连不上数据来源」「没有匹配的岗位」，助手照抄即可。
- 请领导问赵一句：下载索引时的报错原文、操作系统、Python 版本。没有原文复现不了。

**排期：** 0.8.30；兼容问题等原文。

### 第 5 条：盯岗要说清会不会主动通知

**现状：** `watch_intent` 返回 watch_id、status、指纹提示，没有一句「不会主动推送」；`check_watches` 首次返回全量并带 is_first_pull 和 baseline 说明，但助手还是把 11 条说成了新岗。

**做法：**

- `watch_intent` 返回 `matching_now`（当前匹配条数）和 `what_happens_next`（中英）：「已保存条件，现在匹配 N 条，都是已有岗位。OpenHire 不会主动推送；下次对我说『检查一下』，我只列新出现的。要定时提醒，在助手里另设定时任务，到点跑 radar_check。」
- `check_watches` 首次拉取：`new_matches` 保留（兼容），另加 `summary`：「首次检查：当前匹配 N 条，都是已有岗位，不是新发；以后只报新增。」服务器指令加一句：首次拉取不许说成「新出现」。
- 主动推送不做：stdio 没有服务端推送，做了也是假的；定时提醒用助手自己的定时任务。

**排期：** 0.8.30。

### 第 6 条：最后给一张简洁清单

**做法：**

- 每行加 `check_before_apply`，从数据生成的提醒列表：雇主未提供发布日期；在架超过 90 天；薪资未写（10-26 快照 46% 的在架岗位没写）；远程范围不明；投递链接在不认识的域名；雇主自报已关闭；日期是立项日而不是发布日。
- 服务器指令和提示词：第一轮最多 5 条，固定六栏：岗位 · 公司与地点 · 薪资（没写就说雇主没写）· 为什么匹配（matched_skills 加用户自己的条件）· 投递前确认（check_before_apply）· 投递链接；然后问要不要看更多。默认 limit 不改，提示词里的 10 条改 5 条。

**排期：** 0.8.30。

## 七、测量脚本

对 10-26 公开快照（`openhire-index.db.gz` 解压）跑：

```python
import re, sqlite3
c = sqlite3.connect("current.db")
live = c.execute("select count(*) from jobs where delisted_at is null").fetchone()[0]
nodate = c.execute("select count(*) from jobs where delisted_at is null and posted_at is null").fetchone()[0]
sal = c.execute("select count(*) from jobs where delisted_at is null and (salary_min is not null or salary_max is not null)").fetchone()[0]
rows = [t for (t,) in c.execute("select title from jobs where delisted_at is null")]
exec_re = re.compile(r"\b(director|head of|head,|vp\b|vice president|chief|cto|ceo|coo|cfo)\b|总监|总经理|负责人|副总裁|首席", re.I)
mgr_re = re.compile(r"\bmanager\b|经理|主管|leader|lead\b", re.I)
pm_re = re.compile(r"(product|project|program|technical program|account|community|partner(ship)?s?|customer success|office|marketing|brand|content|growth|supply chain|procurement|sales|channel|key account|relationship|portfolio|release|delivery|operations?) manager|产品经理|项目经理|客户经理|销售经理|渠道经理|运营经理|大客户经理|采购经理|供应链经理", re.I)
print(live, nodate, sal,
      sum(1 for t in rows if exec_re.search(t or "")),
      sum(1 for t in rows if mgr_re.search(t or "") and not exec_re.search(t or "")),
      sum(1 for t in rows if mgr_re.search(t or "") and not exec_re.search(t or "") and pm_re.search(t or "")))
```
